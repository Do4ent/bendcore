# Расчётный модуль `src/simulation`: модели и ограничения

Код: `src/simulation/{cfd_solver,thermal_solver,structural_solver,simulation_manager,result_visualization}.cpp`,
заголовки `include/bendcore/simulation/`, пространство имён `BendCore::CadCore::Simulation`.
Входит в `bendcore_core`; потребителей в продукте (CLI, сервер, WASM-мост, `src/ui`) нет —
модуль доступен как библиотека C++. Тесты: `tests/simulation/test_simulation_m6.cpp`
(ctest `simulation_m6`, нужен GTest). Линейная алгебра — Eigen (`SparseLU`).

Все три решателя работают на **облаке узлов** с явными граничными условиями по номерам узлов;
геометрию CAD они не читают, сетку не строят, поля между собой не передают.

## 1. Течение — `CFDSolver`

Стационарное несжимаемое течение на графе узлов (соседи — рёбра тетраэдров сетки, если они
есть, иначе узлы в пределах 1,5 расстояния до ближайшего):

- импульс: `rho (u·grad) u = div((mu + mu_t) grad u)` покомпонентно, противопоточная
  конвекция первого порядка + диффузия на графе, итерации Пикара (на каждой — разреженный LU);
  **давление со скоростью не связано**, неразрывность не обеспечивается (перенос типа Бюргерса);
- давление: уравнение Пуассона `lap(p) = -rho d_i u_j d_j u_i` по сошедшейся скорости
  (абсолютное, опорное 1 атм; `BoundaryCondition::pressure` — избыточное);
- температура: `rho u·grad T = div((k/cp + mu_t/Pr_t) grad T)` (воздух);
- турбулентность: `LAMINAR` или стандартная k-epsilon (Launder–Spalding, интенсивность на входе
  5 %). Для `SPALART_ALLMARAS` и `K_OMEGA_SST` уравнений нет: `solve()` возвращает `false`.

Граничные условия: `DIRICHLET` — скорость (и температура, если > 0 K); `NO_SLIP` — нулевая
скорость; `NEUMANN`, `SLIP`, `MIXED`, `PERIODIC` — нулевая нормальная производная. Части сетки
без закреплённых узлов остаются в начальном состоянии (покой).

Проверки: вязкий предел даёт линейный профиль; при преобладании конвекции решение ограничено и
монотонно; температура переносится вниз по потоку; k-epsilon порождает турбулентность.

## 2. Теплопроводность — `ThermalSolver`

`rho c dT/dt = k lap(T) + q` на единицу объёма, свойства материала постоянны.

- Оператор: `lap(T)_i = sum_j (T_j - T_i) / d_ij^2` по соседям — узлам в пределах 1,2
  расстояния от узла до ближайшего. На регулярной сетке это ровно соседи по граням, оператор
  совпадает с 3/5/7-точечным шаблоном Лапласа (второй порядок). **На нерегулярном облаке
  оператор не согласован** (ошибка не убывает с измельчением) — для таких облаков результат
  качественный.
- Стационарная задача: один разреженный LU; при `RADIATION` — итерации Пикара с
  линеаризацией `h_r = e s (T^2 + T_a^2)(T + T_a)` до изменения < 1e-6 K.
- Нестационарная: неявный (обратный) Эйлер, шаг `setTimeStep`, до `setTotalTime` (последний шаг
  укорачивается); безусловно устойчив, первый порядок по времени. Излучение линеаризуется в
  начале шага, без внутренних итераций.
- ГУ на узлах (`face_indices` — номера узлов): `TEMPERATURE` — фиксирует T; `HEAT_FLUX` и
  `HeatSource` — добавляют Вт/м³ в узел; `CONVECTION` — `h (T - T_a)`; `RADIATION` — см. выше;
  `ADIABATIC` — ничего.
- Тепловой поток в результатах: `q = -k grad T`, градиент — взвешенный МНК по соседям
  (1-D и 2-D облака — через полное ортогональное разложение).
- Без закрепляющих условий (TEMPERATURE, CONVECTION, RADIATION) стационарная задача вырождена,
  `solve()` возвращает `false`.

Проверки (эталоны независимы от кода): линейный профиль стержня с фиксированными концами;
`T = T0 + q/k` в середине стержня с источником; для трёх узлов с фиксированными концами — точная
рекуррентность неявного Эйлера `T_n = 400 - 100 (1 + 2a dt)^-n` и сходимость к решению ОДУ
`400 - 100 exp(-2 a t)` при `dt -> 0`; поток `25 k` Вт/м² на профиле 400→300 K длиной 4 м.

## 3. Линейная упругость — `StructuralSolver`

Статика, малые деформации, изотропный линейно-упругий материал (`E`, `nu`, `-1 < nu < 0,5`).

- Элементы: только линейные тетраэдры (4 узла, постоянная деформация), `K_e = V B^T D B`,
  сдвиги — инженерные, порядок Фойгта `xx, yy, zz, xy, yz, xz`; разреженный LU.
- Нагрузки: только `LoadType::FORCE` (узловые силы). `PRESSURE`, `DISTRIBUTED`, `THERMAL`,
  `DISPLACEMENT` требуют данных о гранях/элементах, которых `Load` не содержит, — `solve()`
  возвращает `false`, а не подменяет их догадкой. Распределённую нагрузку задают
  согласованными узловыми силами (для линейного треугольника — площадь/3 на вершину).
- Закрепления: `FIXED`, `FIXED_X/Y/Z`, `PINNED` (X и Y) задают компоненты перемещения равными
  `Constraint::displacement` (по умолчанию 0). `ROLLER` требует нормали — отклоняется.
- Отказ (`false`): элементы не из 4 узлов или вырожденные, неверный материал, механизм
  (не закреплены перемещения тела как жёсткого целого — LU не проходит или невязка
  > 1e-8 относительно правой части).
- Результаты на элемент: деформация, напряжение (постоянны в элементе), фон Мизес, главные
  напряжения (собственные значения тензора, `sigma1 >= sigma2 >= sigma3`), коэффициент запаса
  `yield_strength / von Mises` (бесконечен для ненагруженного элемента).

Проверки: patch-тест на кубе из 6 тетраэдров — заданное удлинение и согласованные силы на
грани дают однородное одноосное напряжение `sigma`, `eps_xx = sigma/E`, поперечные
`-nu eps`, перемещения `u = (eps x, -nu eps y, -nu eps z)` (закон Гука); один закреплённый узел —
механизм; главные напряжения чистого сдвига `+tau, 0, -tau`.

## 4. Менеджер и визуализация

- `SimulationManager` запускает настроенные решатели. `MULTI_PHYSICS` — **последовательный
  запуск без передачи полей** (у решателей нет общей сетки; прежние «связки» усредняли поле
  или ничего не делали и удалены). Экспорт — сводная таблица `csv`; поля — через
  `ResultVisualization::exportToVTK`.
- `ResultVisualization`: цвета скаляров (JET, HOT, VIRIDIS — по таблице matplotlib, линейная
  интерполяция между 9 опорными значениями), стрелки векторов, уровни контуров (хранятся для
  внешнего отрисовщика), экспорт VTK legacy: облако точек (ячейки `VTK_VERTEX`) со всеми
  полями как `POINT_DATA`; поля на разных узлах в один файл не пишутся (`false`).
  Изоповерхностей нет: у полей нет связности ячеек.

## 5. Как тестировать

```bash
cmake --build build --target test_simulation_m6 && ctest --test-dir build -R simulation_m6
```
