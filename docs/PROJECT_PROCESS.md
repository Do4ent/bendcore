# Регламент разработки bendcore CAD

Действует для всех участников и агентов. Основа — `docs/ROADMAP_GENERAL_CAD.md`.

## 1. Роли

| Роль | Агент | Зона ответственности |
|---|---|---|
| Руководитель проекта | `cad-project-manager` | Декомпозиция фаз на задачи, распределение по ролям, приёмка, слияние веток, журнал проекта |
| Инженер ядра | `cad-kernel-engineer` | Сборка OCCT, `src/kernel/`: форма, сериализация, тесселяция, лечение геометрии, булевы операции |
| Инженер моделирования | `cad-modeling-engineer` | Дерево операций, операции детали, топологическое именование, параметры |
| Инженер сборок | `cad-assembly-engineer` | Документ сборки, решатель сопряжений, интерференция, BOM, библиотека крепежа |
| Инженер чертежей | `cad-drawing-engineer` | Виды и HLR, разрезы, размеры, аннотации ЕСКД/ISO, спецификация, экспорт PDF/DXF/SVG |
| Фронтенд-инженер | `cad-frontend-engineer` | React/three.js интерфейс, WASM-биндинги, вьюпорт, выбор |
| Инженер качества | `cad-qa-engineer` | Корпус эталонных моделей, регрессионные и сквозные тесты, CI, проверка отсутствия заглушек |
| Технический писатель | `cad-tech-writer` | Сводная документация, руководство пользователя, согласованность документов |

Определения агентов: `.claude/agents/<имя>.md`.

## 2. Правило «никаких заглушек»

Запрещено в любом новом или изменённом коде:

- функции, которые возвращают фиксированное значение или `success = true` вместо вычисления;
- комментарии и строки `Placeholder`, `In a real implementation`, `would ...`, `TODO`,
  `FIXME`, `stub`, `not implemented`, `simplified` как описание отсутствующей логики;
- пустые тела функций у объявленной функциональности;
- тесты, которые проверяют только «не упало» или сравнивают с тем же фиксированным значением,
  которое возвращает код.

Если случай не поддерживается — функция возвращает явную ошибку с причиной
(`Result` с кодом и сообщением), а ограничение описывается в документации модуля.
Лучше не объявить функцию, чем объявить и не реализовать.

Проверка: `scripts/check_no_stubs.sh` в CI. Нарушение блокирует слияние.

## 3. Критерии готовности задачи (Definition of Done)

1. Код реализует заявленное поведение на реальной геометрии (OCCT), без заглушек.
2. Модульные тесты проверяют численные результаты против независимого эталона
   (аналитика, известная геометрия, значения из сторонней CAD), а не против самого кода.
3. Сборка и тесты проходят в конфигурации `build-occt` (native, OCCT) и, где применимо, WASM.
4. Документация модуля в `docs/kernel/`, `docs/modeling/`, `docs/assembly/`, `docs/drawing/`
   или `docs/ui/`: назначение, API, алгоритм, ограничения, примеры, как тестировать.
5. Запись в `docs/PROJECT_LOG.md`: что сделано, какие решения приняты и почему.
6. Изменение не трогает файлы других ролей без согласования (раздел 5).

## 4. Сборка и тесты

```bash
# Native с OCCT (основная конфигурация разработки ядра)
cmake -S . -B build-occt -G Ninja -DCMAKE_BUILD_TYPE=RelWithDebInfo \
  -DBENDCORE_WITH_OCCT=ON -DBENDCORE_OCCT_DIR=$PWD/third_party/occt-install
cmake --build build-occt --target <цель>
ctest --test-dir build-occt -R <шаблон> --output-on-failure
```

OCCT не хранится в git (`third_party/occt-install` в `.gitignore`). В отдельных рабочих
копиях (git worktree) указывайте абсолютный путь к основной установке:
`-DBENDCORE_OCCT_DIR=/home/user/bendcore/third_party/occt-install`.

## 5. Владение файлами при параллельной работе

- Каждый модуль подключается в сборку своим файлом `cmake/<модуль>.cmake`,
  который корневой `CMakeLists.txt` включает через `include(... OPTIONAL)`.
  Корневой `CMakeLists.txt` меняют только руководитель проекта и инженер ядра
  (раздел OCCT).
- `.github/workflows/` меняет только инженер качества.
- Общие заголовки `include/bendcore/kernel/` — инженер ядра; остальные роли
  предлагают изменения через руководителя проекта.

## 6. Ветки и слияние

Агенты работают в отдельных рабочих копиях и коммитят в свои ветки. Руководитель проекта
проверяет результат (сборка, тесты, `check_no_stubs.sh`, документация) и сливает в
`ccr-d188a25e-rml7z8`. Коммиты — небольшие, сообщение объясняет «зачем».
