# Экспорт чертежа: DXF, SVG, PDF

API — `include/bendcore/drawing_v2/export.hpp`. Писатели возвращают буфер
(`Result<std::string>`); `saveToFile(path, bytes)` записывает его в файл. Все три формата —
собственные писатели без сторонних библиотек (MIT-совместимо).

Общее для всех форматов: 1 единица = 1 мм листа; штриховка выводится отрезками, найденными
`hatchSegments`; дуга — против часовой стрелки от `startDeg` до `endDeg`.

## DXF — AutoCAD R2000 (AC1015), ASCII

Почему R2000: в R12 нет `LWPOLYLINE` и толщин линий (группа 370); R2007+ требует UTF-8 и
заметно больше обязательных объектов. R2000 читается всеми распространёнными программами.

Состав файла: `HEADER` (`$ACADVER AC1015`, `$DWGCODEPAGE ANSI_1251`, `$INSUNITS 4` — мм,
`$MEASUREMENT 1`, `$EXTMIN/$EXTMAX`, `$LIMMIN/$LIMMAX` — размер листа, `$LTSCALE 1`,
`$HANDSEED`), `CLASSES` (пустая), `TABLES` — `VPORT` (*Active на весь лист), `LTYPE`
(ByBlock, ByLayer, Continuous и шаблоны ГОСТ: `GOST_DASHED`, `GOST_DASHDOT_THIN`,
`GOST_DASHDOT_THICK`, `GOST_DASHDOTDOT`, элементы 49 в мм), `LAYER` (цвет 62), `STYLE`
(`GOST_UPRIGHT`, `GOST_SLANT` с наклоном 15°, шрифт `DejaVuSans.ttf`), `VIEW`, `UCS`,
`APPID`, `DIMSTYLE`, `BLOCK_RECORD`; `BLOCKS` (*Model_Space, *Paper_Space); `ENTITIES`;
`OBJECTS` (корневой словарь и `ACAD_GROUP`). У каждого объекта — дескриптор (5) и владелец
(330).

Сущности: `LINE`, `ARC`, `CIRCLE`, `LWPOLYLINE` (флаг 128 — непрерывный шаблон по всей
полилинии), `TEXT` (40 — высота прописных, 41 — коэффициент ширины, 50 — поворот,
51 — наклон 15°, 72/73 и точка 11 — выравнивание). Каждая сущность несёт слой (8), тип
линии (6) и толщину (370) — ближайшее значение из стандартного набора AutoCAD
(`dxfLineweight`: 0,25 → 25; 0,333 → 35; 0,75 → 70); точная толщина остаётся в SVG/PDF.

Кириллица. В DXF до R2007 строки — однобайтовые в кодовой странице `$DWGCODEPAGE`; любой
символ Unicode из BMP записывается последовательностью `\U+XXXX` (так пишет сам AutoCAD
R2000–R2004). Писатель выводит чистый ASCII: не-ASCII символы — `\U+XXXX`,
`$DWGCODEPAGE = ANSI_1251` для программ, которые смотрят на кодовую страницу. Плюсы: файл
не зависит от кодовой страницы читателя, работают и символы вне cp1251 (Ø, °, ±, №).
Символы вне BMP (> U+FFFF) так не записываются — ошибка `Unsupported`.

## SVG 1.1

`width="<W>mm" height="<H>mm" viewBox="0 0 W H"` — 1 единица пользователя = 1 мм, печать
без масштабирования даёт 1:1. Ось Y переворачивается координатами (y_svg = H − y), без
`transform` на группах, поэтому числа в файле прямо сверяются с моделью. Слой → `<g
id="layer-NAME">`. Линии: `stroke-width` = толщина ГОСТ в мм, `stroke-dasharray` из шаблона
(`renderDashArray`), `stroke-linecap="butt"`; атрибут `data-linetype` — имя типа линии.
Дуга — `path` с командой `A` (sweep-flag 0 = против часовой стрелки на листе). Текст —
`<text>` с `font-size = h / (capHeight/unitsPerEm)` (по шрифту из `SvgOptions::font` или
`capHeightRatio`, 0,729 для DejaVu Sans), `text-anchor` для выравнивания по горизонтали,
`transform="translate(x y) rotate(-α) translate(0 dy) skewX(-15) scale(k 1)"`. Шрифт в SVG
не встраивается — указывается `font-family="DejaVu Sans"`; при отсутствии шрифта у
просмотрщика ширина строк будет другой (высота прописных — тоже, если у замены другая
пропорция).

## PDF 1.4, векторный

- Одна страница, `MediaBox [0 0 W·72/25,4 H·72/25,4]`: А4 = 595,2756 × 841,8898 pt,
  А3 альбомный = 1190,5512 × 841,8898 pt.
- Координаты содержимого — сразу в пунктах (без `cm`), 4 знака после точки; начало — левый
  нижний угол, как в модели.
- Линии: `w` — толщина ГОСТ, `d` — шаблон штрихов в пунктах, `J 0` (без выступа),
  `j 1`. Окружность и дуга — кубические Безье по ≤ 90° (`k = 4/3·tan(θ/4)`, отклонение от
  окружности ≤ 2,7·10⁻⁴ r).
- Таблица `xref` — записи ровно по 20 байт, смещения указывают на `n 0 obj`; `/Length`
  потоков точный; сжатия нет (zlib в проекте не используется).
- Текст: шрифт TrueType встраивается целиком (`FontFile2`, `/Length1` = размер файла) как
  `CIDFontType2` + `Type0` с кодировкой `Identity-H` (код = индекс глифа,
  `CIDToGIDMap /Identity`), массив ширин `W` для использованных глифов, карта `ToUnicode`
  (поиск и копирование текста, `pdftotext`). Кегль = h / (capHeight/unitsPerEm), матрица
  `Tm = [k·cos k·sin (t·cos − sin) (t·sin + cos) x y]`, где t = tan 15° — наклон 75°,
  k — коэффициент ширины. Выравнивание по ширине строки из `hmtx` (без кернинга).
- Символ, которого нет в шрифте, — ошибка `Unsupported`; текст без шрифта — `InvalidInput`.
- `/Info /Title` — UTF-16BE.

Размер: шрифт встраивается целиком (DejaVu Sans — 742 КБ), PDF с текстом ≈ 770 КБ.
Подмножество шрифта (subset) не реализовано.

### Шрифты и лицензии

Шрифт не хранится в репозитории — берётся из системы (`findSystemFont`): переменная
`BENDCORE_DRAWING_FONT`, затем стандартные пути DejaVu Sans и Liberation Sans
(`defaultFontCandidates`).

| Шрифт | Лицензия | Встраивание |
|---|---|---|
| DejaVu Sans | Bitstream Vera Fonts License (+ public domain для изменений DejaVu) — пермиссивная | разрешено, `fsType = 0` |
| Liberation Sans | SIL Open Font License 1.1 | разрешено |

Шрифт с `OS/2 fsType` = Restricted License отвергается (`Unsupported`). Поддерживаются
только шрифты с контурами TrueType (`glyf`); OpenType-CFF (`.otf`) — ошибка.

## Как проверяется

`ctest --test-dir build-occt -R drawing_v2 --output-on-failure`; файлы пишутся в
`build-occt/drawing_v2_out/` (`sample_a3.dxf/.svg/.pdf`, `sample_a4.pdf`).

- DXF (`test_dxf.cpp`): файл читается собственным разборщиком групповых кодов в тестах
  (`src/dxf_reader.cpp` не годится — он не разбирает координаты); проверяются порядок
  секций, переменные HEADER, уникальность дескрипторов и `$HANDSEED`, шаблоны LTYPE, слои,
  стили, число и координаты LINE/ARC/CIRCLE/LWPOLYLINE/TEXT против модели, слой/тип/толщина
  каждой линии, тексты основной надписи после декодирования `\U+XXXX`. Если задана
  переменная `BENDCORE_PYTHON_EZDXF` (python с пакетом ezdxf, MIT), файл дополнительно
  читается ezdxf: версия AC1015, `audit()` без ошибок, число сущностей совпадает,
  `$INSUNITS = 4`, кириллица декодируется `ezdxf.decode_dxf_unicode`. Проверено с ezdxf 1.4.5.
- SVG (`test_svg.cpp`): атрибуты `svg`, координаты отрезков/окружности/дуги/полилинии с
  переворотом Y, толщины и `stroke-dasharray` по ГОСТ, кегль по метрикам шрифта, тексты;
  `xmllint --noout`, если установлен.
- PDF (`test_pdf.cpp`): разбор xref (каждое смещение указывает на объект), `/Length`
  потоков, MediaBox А3/А4, координаты отрезков и рамки в пунктах, толщины и шаблоны,
  точки Безье окружности на окружности, матрица текста (наклон 15°), кегль, встроенный
  шрифт байт в байт, ширины W, ToUnicode; программы poppler, если установлены: `pdfinfo`
  (размер страницы «A3», заголовок), `pdffonts` (CID TrueType, Identity-H, встроен, есть
  ToUnicode), `pdftotext` (кириллические тексты основной надписи).
- Шрифт (`test_font.cpp`): метрики DejaVu Sans против значений fontTools (unitsPerEm 2048,
  индексы и ширины глифов H, А, Я, ж, пробела, высота прописных 1493); отказ для
  шрифта с запретом встраивания.

Не проверено: открытие файлов в AutoCAD, Компас, Acrobat — этих программ в среде
разработки нет. Объекты LAYOUT в DXF не пишутся (ezdxf создаёт их при чтении; AutoCAD
обычно восстанавливает их сам, но это не проверялось).
