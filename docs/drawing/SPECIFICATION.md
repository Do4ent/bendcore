# Спецификация ГОСТ 2.106 и перечень составных частей ISO 7573

Фаза 4, п. 7 `docs/ROADMAP_GENERAL_CAD.md`. Заголовок `include/bendcore/drawing_v2/specification.hpp`,
исходник `src/drawing_v2/annotations/specification.cpp`, цель `bendcore_drawing_annotations`
(`ANNOTATIONS.md`). Источник данных — документ сборки (`docs/assembly/ASSEMBLY_DOCUMENT.md`,
раздел 8), функция `assembly_v2::structuredBom` используется только для чтения.

## Состав из BOM

`buildSpecification(document, options)`:

1. Строки `structuredBom` уровня 0 — составные части корневой сборки с количеством на одну
   сборку. Состав подсборок в спецификацию не входит (у сборочной единицы своя спецификация).
2. Раздел (ГОСТ 2.106-96, разд. 3: «Документация», «Комплексы», «Сборочные единицы»,
   «Детали», «Стандартные изделия», «Прочие изделия», «Материалы», «Комплекты»):
   сборка → «Сборочные единицы», деталь с обозначением → «Детали», деталь без обозначения →
   «Стандартные изделия». Иначе — `SpecificationOptions::sectionOverride` (например, кольцо по
   ТУ → «Прочие изделия», краска → «Материалы»). В BOM нет признака «стандартное изделие» —
   правило «нет обозначения» — допущение проекта.
3. «Документация»: при `addAssemblyDrawing` — «<обозначение> СБ», «Сборочный чертёж»
   (формат `assemblyDrawingFormat`, по умолчанию А3), затем `options.documents`. Без позиций и
   количества.
4. Порядок внутри раздела: «Комплексы», «Сборочные единицы», «Детали», «Комплекты» — по
   возрастанию обозначений; «Стандартные изделия», «Прочие изделия», «Материалы» — по
   наименованию, затем по обозначению. Сравнение «естественное»: числа внутри строк —
   по значению («Болт М6» < «Болт М10», «РД.00.002» < «РД.00.0005»). ГОСТ 2.106 для
   стандартных изделий требует группировку по категориям стандартов (межгосударственные,
   государственные, отраслевые…) и затем по алфавиту наименований — категории не
   различаются (**ограничение**).
5. Позиции — сквозная нумерация в порядке записи, начиная с 1, кроме «Документации»;
   `reservePositions` — резервные номера после каждого раздела.
6. Графы «Формат» и «Примечание» — `options.formats`, `options.notes` по определению.

`Specification::positionOf(definition)` — номер позиции определения (для выносок).

## Листы — форма 1 ГОСТ 2.106-96

`renderSpecification(spec, options)` → `SpecDocument {sheets, rows, firstSheetRows, otherSheetRows}`.

- Лист А4 книжной ориентации, рамка с полями 20/5 мм, графы 19–23 (по умолчанию).
- Графы формы 1, мм: «Формат» 6, «Зона» 6, «Поз.» 8, «Обозначение» 70, «Наименование» 63,
  «Кол.» 10, «Примечание» 22 (всего 185); строка заголовков 15 мм, строки 8 мм. Заголовки
  «Формат», «Зона», «Поз.» — повёрнуты на 90°. Вертикали граф и линия под заголовками —
  сплошные основные, строки — тонкие.
- Первый лист — основная надпись формы 2 (185×40), последующие — формы 2а (185×15); отсюда
  ёмкость 29 строк на первом листе ((287 − 40 − 15)/8) и 32 на последующих ((287 − 15 − 15)/8).
- Записи раздела: пустая строка, заголовок (по центру графы «Наименование», подчёркнут тонкой
  линией), пустая строка, позиции. Наименование переносится по словам в пределах графы
  (61 мм при h = 3,5): номер позиции, обозначение и количество — в первой строке записи.
  Пустая строка перед заголовком в начале листа опускается. Запись (все её строки) не
  разрывается между листами; заголовок раздела переносится на следующий лист вместе с
  первой строкой первой позиции.
- Текст ячеек — ГОСТ 2.304, h = 3,5 (заголовки граф — до 5), при нехватке места — сжатие до
  0,6 и уменьшение высоты до 2,5 (по шрифту, если задан `SpecSheetOptions::font`, иначе по
  оценке шрифта типа Б); не помещается — ошибка с именем графы.
- Основная надпись: обозначение и наименование — из спецификации, «Лист»/«Листов» — по
  числу листов.
- Экспорт: каждый лист — `writeDxf`/`writeSvg`; все листы одним PDF — `writePdfPages`.

### Основная надпись формы 2 (ГОСТ 2.104-2006)

185×40, координаты от левого нижнего угла надписи: левая часть 65 мм (колонки 7, 10, 23, 15,
10): строки изменений 30…40 (две по 5 мм), заголовок «Изм., Лист, № докум., Подп., Дата» 25…30,
подписи 0…25 («Разраб.», «Пров.», резерв, «Н.контр.», «Утв.»); графа 2 — 65…185 × 25…40;
графа 1 — 65…135 × 0…25; «Лит.» (3 клетки по 5) 135…150, «Лист» 150…165, «Листов» 165…185 —
заголовки 20…25, значения 15…20; графа 9 — 135…185 × 0…15.

## Перечень составных частей на поле чертежа — ISO 7573

`addPartsList(drawing, titleLayout, spec, options)`: таблица шириной 185 мм над основной
надписью, строка заголовков примыкает к основной надписи, позиции — снизу вверх по
возрастанию номеров. Графы по умолчанию: «Item» 15, «Qty» 15, «Title / Name» 60, «Reference»
50, «Material» 45 (заголовки и ширины задаются в `PartsListOptions`). Номера — те же, что в
спецификации ГОСТ 2.106.

## Синхронизация позиций с выносками

`synchronizeBalloons(balloons, spec)`: номер каждой выноски (`Balloon::definition`) берётся из
спецификации; выноска на определение, которого нет в спецификации (например, деталь внутри
подсборки), — ошибка `InvalidInput`. Отчёт: позиции без выноски, определения с несколькими
выносками. После изменения состава сборки спецификацию строят заново и вызывают
`synchronizeBalloons` — номера на чертеже следуют новому порядку.

## Требует сверки

- Ширины граф формы 1 (6, 6, 8, 70, 63, 10, 22), высоты строк 15 и 8 мм, размеры граф формы 2
  ГОСТ 2.104 — по изображениям форм; официальных текстов ГОСТ 2.106-96 и ГОСТ 2.104-2006 в
  среде разработки нет.
- Правило размещения количества при наименовании в несколько строк (здесь — в первой строке).
- Ширины граф и заголовки перечня ISO 7573 (стандарт не фиксирует ширины; выбраны проектом).

## Ограничения

- Графа «Зона» не заполняется автоматически (нет разбивки поля чертежа на зоны).
- Нет листа регистрации изменений и раздела «Переменные данные для исполнений» (ГОСТ 2.113).
- Категории стандартов внутри «Стандартных изделий» не различаются (см. выше).

## Как тестировать

`ctest --test-dir build-occt -R drawing_annotations --output-on-failure`.

- `test_annotations_specification.cpp` — сборка «Редуктор» (корпус, вал, крышка в сборе,
  болты М10 ×4 и М6 ×6, шайбы ×6, кольцо как прочее изделие), детали вставлены не в порядке
  спецификации: разделы в порядке ГОСТ, «РД.00.000 СБ» без позиции, сборочная единица —
  позиция 1, детали РД.00.001/002 — 2 и 3, «Болт М6» (4) раньше «Болт М10» (5), шайба 6,
  кольцо 7, количества 6 и 4, прокладка из подсборки отсутствует, резерв 2 номера; 30 штифтов
  → несколько листов: ёмкость 29/32, заголовок не последний на листе, сквозные номера,
  перенос наименований, форма 2 только на первом листе; перечень ISO 7573 (высота
  8·(7 + 1), ширина 185, «1» ниже «7»), синхронизация выносок и перенумерация после вставки
  детали РД.00.0005.
- `test_annotations_export.cpp, SpecificationMultiPagePdf` — спецификация узла на нескольких
  листах → `build-occt/drawing_annotations_out/specification.pdf`: `/Count` страниц,
  MediaBox А4, `pdfinfo` (число страниц), `pdftotext` — «Документация» < «Детали» <
  «Стандартные изделия», «Сборочный чертёж», «РД.00.000 СБ», «Винт М4×6» раньше «Винт М4×10».
