# Спецификация ГОСТ 2.106 и перечень составных частей ISO 7573

Фаза 4, п. 7 `docs/ROADMAP_GENERAL_CAD.md`. Заголовок `include/bendcore/drawing_v2/specification.hpp`,
исходник `src/drawing_v2/annotations/specification.cpp`, цель `bendcore_drawing_annotations`
(`ANNOTATIONS.md`). Источник данных — документ сборки (`docs/assembly/ASSEMBLY_DOCUMENT.md`,
раздел 8), функция `assembly_v2::structuredBom` используется только для чтения.

## Состав из BOM

`buildSpecification(document, options)`:

1. Строки `structuredBom` уровня 0 — составные части корневой сборки с количеством на одну
   сборку. Подсборка — сборочная единица со своей позицией; её состав в спецификацию не
   входит (у сборочной единицы своя спецификация, ГОСТ 2.106-96, разд. 3). Исключение —
   «разборные» подсборки `SpecificationOptions::dissolve` (определения-сборки, которые не
   являются сборочными единицами, например узел, собранный только для удобства моделирования):
   вместо них записывается их состав (рекурсивно, количество умножается на число вхождений,
   одинаковые определения суммируются). В документе спецификации — `SpecificationSettings::
   dissolved` (ключи составных частей: обозначение или наименование), в файле —
   `"dissolvedAssemblies"`; в WASM — `setSettings({dissolvedAssemblies})`.
2. Раздел (ГОСТ 2.106-96, разд. 3: «Документация», «Комплексы», «Сборочные единицы»,
   «Детали», «Стандартные изделия», «Прочие изделия», «Материалы», «Комплекты»):
   сборка → «Сборочные единицы», деталь с обозначением → «Детали», деталь без обозначения →
   «Стандартные изделия». Иначе — `SpecificationOptions::sectionOverride` (например, кольцо по
   ТУ → «Прочие изделия», краска → «Материалы»). В BOM нет признака «стандартное изделие» —
   правило «нет обозначения» — допущение проекта.
3. «Документация»: при `addAssemblyDrawing` — «<обозначение> СБ», «Сборочный чертёж»
   (формат `assemblyDrawingFormat`, по умолчанию А3), затем `options.documents`. Без позиций и
   количества.
4. Порядок внутри раздела: «Комплексы», «Сборочные единицы», «Детали», «Комплекты» — по
   возрастанию обозначений; «Стандартные изделия», «Прочие изделия», «Материалы» — по
   наименованию, затем по обозначению. Сравнение «естественное»: числа внутри строк —
   по значению («Болт М6» < «Болт М10», «РД.00.002» < «РД.00.0005»). ГОСТ 2.106 для
   стандартных изделий требует группировку по категориям стандартов (межгосударственные,
   государственные, отраслевые…) и затем по алфавиту наименований — категории не
   различаются (**ограничение**).
5. Позиции — сквозная нумерация в порядке записи, начиная с 1, кроме «Документации»;
   `reservePositions` — резервные номера после каждого раздела.
6. Графы «Формат» и «Примечание» — `options.formats`, `options.notes` по определению.

`Specification::positionOf(definition)` — номер позиции определения (для выносок).

Позиции на сборочном чертеже (ГОСТ 2.109): номер позиции ребра вида — у первого определения
цепочки вхождений детали от верхнего уровня, которое есть в спецификации
(`document::positionOwner`, `ModelSnapshot::childChain/edgeChild`). Поэтому подсборка —
сборочная единица получает одну позицию, выноска ставится на видимую линию любой её детали, а
детали подсборки своих номеров не получают; у «разборной» подсборки номера получают её детали.
Ручная позиция на ребре детали подсборки получает номер подсборки.

Шрифт листов — `SpecificationSettings::textFont` (по умолчанию ГОСТ 2.304, `EXPORT.md`);
подгонка текста в графы шрифтом ГОСТ — уменьшением высоты без сжатия (`SpecSheetOptions::
font`, `textFont`).

## Исполнения деталей

Деталь с таблицей параметров (`docs/modeling/PART_DOCUMENT.md`, «Таблица параметров») входит в
сборку исполнениями: у каждого используемого исполнения своё определение с источником
`«<путь>#<исполнение>»` и свойствами исполнения (`docs/assembly/ASSEMBLY_DOCUMENT.md`,
раздел 8.1). Поэтому в спецификации исполнения — **отдельные строки** раздела «Детали» со
своими полными обозначениями («РЦ.080.00.010», «РЦ.080.00.010-01», …), наименованиями,
количествами и номерами позиций; порядок — по возрастанию обозначений (базовое исполнение
раньше «-01», «-01» раньше «-02»). Это запись исполнений как самостоятельных составных частей
(ГОСТ 2.106, ГОСТ 2.113, п. 5 — спецификация конкретного исполнения сборочной единицы).

Групповая спецификация ГОСТ 2.113 по исполнениям сборки — разделы «Исполнения сборки» и
«Групповая спецификация ГОСТ 2.113» ниже.

Тест: `test_annotations_specification.cpp, Specification.PartConfigurationsAreSeparateRows` —
документ детали с исполнениями РЦ.080.00.010 (W = 60), -01 (W = 80), -02 (W = 40, другое
наименование) из источника в памяти, пять вхождений (2 базовых, 2 «-01», 1 «-02»): три строки
«Детали» в порядке обозначений, количества 2/2/1, позиции 1–3, `positionOf` определения «-01».

## Исполнения сборки

У документа сборки может быть таблица исполнений (`docs/assembly/ASSEMBLY_DOCUMENT.md`,
раздел 8.2): исключение компонентов, исполнение детали или подсборки у вхождения, значения
сопряжений. **Спецификация ГОСТ 2.106 активного исполнения** строится как обычно: документ
хранит действующий состав, `structuredBom` даёт его составные части и количества (исключённые
компоненты в BOM не входят), обозначение и наименование сборки исполнения —
`AssemblyDocument::configurationProperties()` («РЦ.100.00.000-01», наименование строки).

**Состав всех исполнений сразу** — для групповой спецификации ГОСТ 2.113 (графа «Кол.» по
исполнениям или раздел «Переменные данные для исполнений» — раздел «Групповая спецификация
ГОСТ 2.113» ниже):

```cpp
#include <bendcore/assembly_v2/bom.hpp>

kernel::Result<assembly_v2::ConfigurationBom>
assembly_v2::configurationBom(const AssemblyDocument& document, const LoadOptions& options = {});
```

| Поле | Содержимое |
|---|---|
| `configurations[i]` | исполнение i — строка таблицы по порядку: `designation` («-01»), `fullDesignation` («РЦ.100.00.000-01»), `name`, `totalMass` (кг, `nullopt` — масса известна не для всех деталей), `totalVolume`, `totalParts` |
| `rows[j]` | составная часть первого уровня (как `structuredBom`, уровень 0 — то, что записывается в спецификацию): `definition`, `kind` (деталь / сборочная единица), `designation`, `name`, `material`, `unitVolume`, `unitMass`, `quantities[i]` — количество в исполнении i (0 — нет в нём) |
| `parts[j]` | все детали изделия по дереву (как `flatBom`), те же поля |

Порядок строк — первое появление по исполнениям; одна строка на определение, определения с
теми же видом, обозначением, наименованием, материалом, объёмом и массой сводятся в одну
(встроенная деталь двух исполнений внешней подсборки). Исполнение компонента — отдельная
строка со своим обозначением (раздел «Исполнения деталей»). Строка, у которой количества
во всех исполнениях равны, — постоянная часть спецификации (ГОСТ 2.113, п. 4), остальные —
переменные данные. `options` загружает исполнения компонентов, которых ещё нет в документе
(`fileLoadOptions` или источники в памяти); документ не меняется (исполнения активируются на
копии без решения сопряжений). Таблица без строк — один столбец с текущим составом. Ошибки:
активации исполнения и BOM — с префиксом «configuration '-01': ».

Пример: `test_assembly_document_assembly_configurations.cpp,
AssemblyConfigurations.GearboxMassBomDofInterferencePerConfiguration` — корпус 1/1/1, болт
М10×30 2/0/2, болт М10×40 0/4/0, вал трёх исполнений 1/0/0, 0/1/0, 0/0/1. В WASM —
`configurationBom()` документа сборки (`docs/ui/ASSEMBLY_UI.md`).

## Групповая спецификация ГОСТ 2.113

Заголовок `include/bendcore/drawing_v2/group_documents.hpp`, исходник
`src/drawing_v2/annotations/group_documents.cpp`; документ — `SpecificationDocument` в групповом
режиме (`SpecificationSettings::group`, `docs/drawing/DRAWING_DOCUMENT.md`).

```cpp
Result<GroupSpecification> buildGroupSpecification(const assembly_v2::ConfigurationBom& bom,
                                                   std::string designation, std::string name,
                                                   const GroupSpecOptions& options = {});
Result<SpecDocument> renderGroupSpecification(const GroupSpecification& spec,
                                              const SpecSheetOptions& options = {});
```

**Состав.** Строки `configurationBom` (уровень 0 по всем исполнениям) — составные части с
количеством в каждом исполнении (`GroupSpecItem::quantities`, 0 — нет в исполнении). Разделы,
порядок внутри раздела, «Документация» (групповой сборочный чертёж «<обозначение базового
исполнения> СБ»), графы «Формат» и «Примечание», резерв позиций — как у `buildSpecification`
(ГОСТ 2.106). Строка, у которой количества во всех исполнениях равны, — постоянная
(`GroupSpecItem::constant()`, ГОСТ 2.113, п. 4), остальные — переменные данные. Обозначение и
наименование документа — базового исполнения (`configurations[0].fullDesignation`, свойства
корня), основная надпись листов — тоже.

**Способы записи** (`GroupSpecLayout`, ГОСТ 2.113, разд. 4):

| Способ | Графы | Позиции |
|---|---|---|
| `Columns` (по умолчанию) | графа «Кол. на исполн.» делится на графы по исполнениям: заголовки — суффиксы обозначений без «-» («01», «02»), у базового исполнения без суффикса — «–»; в строке — количество или «–» | сквозные, в порядке записи |
| `VariableData` | обычная форма 1 (одна графа «Кол.»); постоянная часть — в разделах; затем заголовок «Переменные данные для исполнений» и для каждого исполнения — заголовок с его полным обозначением и разделы с переменными составными частями этого исполнения (количество в нём) | постоянная часть, затем переменные; номер позиции составной части один во всех исполнениях |

Ширины граф `Columns` (`groupSpecColumnWidths`): «Формат» 6, «Зона» 6, «Поз.» 8, «Обозначение» 70,
графы количества по 10 мм (до 4 исполнений) или 8 мм (5–7), «Примечание» 22 (12 при 5–7),
«Наименование» — остаток до 185 мм (не меньше 27 мм); больше 7 исполнений — ошибка
`InvalidInput` (используйте `VariableData`). Общий заголовок «Кол. на исполн.» — над графами
количества, если не помещается — «Кол.»; вертикали между графами количества не пересекают общий
заголовок. Строка листа — `SpecRow` с `quantities` (по исполнениям). Заголовки граф количества
задаёт пользователь (`GroupSpecOptions::columnHeaders`, в документе —
`GroupSpecificationSettings::columnHeaders`, в WASM — `setSettings({groupSpecification:
{columnHeaders}})`; пустая строка — по умолчанию).

**Позиции сборочного чертежа.** `SpecificationDocument::specification()` в групповом режиме —
`GroupSpecification::forConfiguration(активное)`: составные части активного исполнения с
количеством в нём и номерами позиций групповой спецификации; определения строк (из копии
документа, на которой `configurationBom` активировал исполнения) сопоставляются с составом
документа по обозначению и наименованию. Поэтому выноски сборочного чертежа совпадают с
групповой спецификацией.

**Экспорт** — тем же путём, что обычная спецификация: `SpecificationDocument::render` выдаёт
листы групповой спецификации, `exportKit` пишет их в общий PDF и в `<base>_SP<n>.dxf/.svg`; в
WASM — `exportPdf` (листы спецификации после листов чертежа).

Ошибки: нет исполнений; составная часть без наименования; «разборные» подсборки
(`dissolvedAssemblies`) — групповой режим их не поддерживает (`InvalidInput`); ошибки
`configurationBom` с префиксом «group specification: configuration '-01': ».

Тест: `test_drawing_document_group.cpp, DrawingDocumentGroup.AssemblyGroupSpecificationQuantitiesPerConfiguration`
— сборка «Рамка» РЦ.200.00.000 с исполнением «-01»: основание ×1/1, планка РЦ.080.00.010 ×2/1,
её исполнение «-01» ×0/1, штифт ×4/2. Количества групповой спецификации совпадают с
`configurationBom` и с независимым подсчётом по ячейкам таблицы исполнений; позиции 1–4; строки
листа («–», «1»), примечание по ключу; заголовки граф — правка и файл; комплект PDF/DXF/SVG
(`exportKit`): тексты DXF и ezdxf `audit()`, `pdftotext` — разделы и обозначения; способ
`VariableData` — порядок заголовков и строк, позиции (основание 1, затем переменные 2–4).

## Листы — форма 1 ГОСТ 2.106-96

`renderSpecification(spec, options)` → `SpecDocument {sheets, rows, firstSheetRows, otherSheetRows}`.

- Лист А4 книжной ориентации, рамка с полями 20/5 мм, графы 19–23 (по умолчанию).
- Графы формы 1, мм: «Формат» 6, «Зона» 6, «Поз.» 8, «Обозначение» 70, «Наименование» 63,
  «Кол.» 10, «Примечание» 22 (всего 185); строка заголовков 15 мм, строки 8 мм. Заголовки
  «Формат», «Зона», «Поз.» — повёрнуты на 90°. Вертикали граф и линия под заголовками —
  сплошные основные, строки — тонкие.
- Первый лист — основная надпись формы 2 (185×40), последующие — формы 2а (185×15); отсюда
  ёмкость 29 строк на первом листе ((287 − 40 − 15)/8) и 32 на последующих ((287 − 15 − 15)/8).
- Записи раздела: пустая строка, заголовок (по центру графы «Наименование», подчёркнут тонкой
  линией), пустая строка, позиции. Наименование переносится по словам в пределах графы
  (61 мм при h = 3,5): номер позиции, обозначение и количество — в первой строке записи.
  Пустая строка перед заголовком в начале листа опускается. Запись (все её строки) не
  разрывается между листами; заголовок раздела переносится на следующий лист вместе с
  первой строкой первой позиции.
- Текст ячеек — ГОСТ 2.304, h = 3,5 (заголовки граф — до 5), при нехватке места — сжатие до
  0,6 и уменьшение высоты до 2,5 (по шрифту, если задан `SpecSheetOptions::font`, иначе по
  оценке шрифта типа Б); не помещается — ошибка с именем графы.
- Основная надпись: обозначение и наименование — из спецификации, «Лист»/«Листов» — по
  числу листов.
- Экспорт: каждый лист — `writeDxf`/`writeSvg`; все листы одним PDF — `writePdfPages`.

`addPartsList(drawing, titleLayout, spec, options)`: таблица шириной 185 мм над основной

## Синхронизация позиций с выносками

`synchronizeBalloons(balloons, spec)`: номер каждой выноски (`Balloon::definition`) берётся из
спецификации; выноска на определение, которого нет в спецификации (например, деталь внутри
подсборки), — ошибка `InvalidInput`. Отчёт: позиции без выноски, определения с несколькими
выносками (в документе чертежа выноски ставятся только на позиции, найденные по цепочке
вхождений, поэтому этой ошибки там не бывает). После изменения состава сборки спецификацию строят заново и вызывают
`synchronizeBalloons` — номера на чертеже следуют новому порядку.

## Графа «Зона» — ГОСТ 2.106-96, ГОСТ 2.104-2006

В графе «Зона» спецификации указывают обозначение зоны сборочного чертежа, в которой находится
номер позиции составной части (ГОСТ 2.106-96, разд. 3, описание граф формы 1). Зоны размечаются
на полях листа чертежа (`DrawingSettings::zones`, `DRAWING_MODEL.md`, «Зоны поля чертежа»).

- `DrawingDocument::positionZones()` — после `update`: для каждой составной части с позицией на
  листе с разметкой зон — зона центра номера позиции (середина текста над полкой или центр
  кружка, `balloonGeometry`); на нескольких листах — первая по порядку листов и позиций
  (автоматические позиции видов, затем ручные).
- `SpecificationDocument::setPositionZones(zones)` — записывает зоны в позиции спецификации по
  определению (графа пуста у документации, у позиции без выноски и при выключенных зонах); зоны
  хранятся в документе (не в файле) и применяются при каждом `update`. Групповая спецификация
  ГОСТ 2.113 получает зону по номеру позиции. Изменение графы входит в признак изменения состава
  (`sameContent`).
- Интерфейс (`bendcore_drawing_wasm`) после каждого обновления чертежа передаёт
  `positionZones()` спецификации: графа видна во вкладке «Спецификация» и на листах формы 1.
- Обозначение — «буква + цифра» (ЕСКД — «Б3», ISO — «B3»); номер листа сборочного чертежа в
  графу не добавляется (`STANDARDS_VERIFICATION.md`).

  ГОСТ 2.104 — по изображениям форм; официальных текстов ГОСТ 2.106-96 и ГОСТ 2.104-2006 в
  среде разработки нет.
- Правило размещения количества при наименовании в несколько строк (здесь — в первой строке).
- Ширины граф и заголовки перечня ISO 7573 (стандарт не фиксирует ширины; выбраны проектом).
- Групповая спецификация ГОСТ 2.113: ширины и заголовки граф количества по исполнениям, запись
  заголовка исполнения в разделе «Переменные данные для исполнений» (`docs/STANDARDS_VERIFICATION.md`).
- Признак «разборной» подсборки задаётся пользователем: ГОСТ 2.106 и ГОСТ 2.109 не дают
  правила, по которому модель сборки сама определяет, что подсборка не является сборочной
  единицей.

## Ограничения

- Графа «Зона» — по первой выноске позиции; позиция на нескольких листах сборочного чертежа
  получает зону первого листа без номера листа.
- Нет листа регистрации изменений. Групповая спецификация ГОСТ 2.113 — раздел «Групповая
  спецификация ГОСТ 2.113»: «разборные» подсборки в ней не поддерживаются, графы количества —
  до 7 исполнений (больше — способ «Переменные данные для исполнений»).
- Категории стандартов внутри «Стандартных изделий» не различаются (см. выше).
