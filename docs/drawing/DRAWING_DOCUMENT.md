# Документ чертежа (`bendcore_drawing_document`)

Фаза 4 `docs/ROADMAP_GENERAL_CAD.md` — сквозной результат: документ детали или сборки →
документ чертежа → комплект PDF/DXF/SVG. Модуль связывает построители видов
(`VIEWS.md`), размеры и аннотации (`ANNOTATIONS.md`), спецификацию (`SPECIFICATION.md`),
модель листа и экспорт (`DRAWING_MODEL.md`, `EXPORT.md`).

- Заголовок: `include/bendcore/drawing_v2/drawing_document.hpp`, пространство имён
  `bendcore::drawing_v2::document`.
- Исходники: `src/drawing_v2/document/` — `model_snapshot.cpp` (снимки модели, загрузка по
  пути), `drawing_document.cpp` (проверка, обновление, компоновка, вывод листов),
  `serialization.cpp` (формат файла, миграция), `specification_document.cpp` (спецификация,
  экспорт комплекта).
- Сборка: `cmake/drawing_document.cmake`, цель `bendcore_drawing_document` (зависит от
  `bendcore_drawing_annotations`; только при `BENDCORE_WITH_OCCT=ON`). nlohmann/json (MIT) —
  только для формата файла.
- Ошибки — `Result`/`Status` с кодом; размеры и знаки, чьи элементы модели исчезли, — не
  ошибка, а «висячие» элементы в отчёте обновления.

## Модель

`ModelLink {kind, path, resultHash, revision, properties}` — ссылка документа на модель: вид
(деталь/сборка), путь к файлу документа (относительно файла чертежа), хэш формы результата
при последнем обновлении (`views::shapeContentHash`, 16 hex — тот же ключ, что у кэша видов)
и счётчик ревизий (растёт, когда при обновлении хэш изменился).

`ModelSnapshot` — состояние модели для обновления:

| Источник | Функция | Форма | Имена ссылок | Свойства основной надписи |
|---|---|---|---|---|
| Документ детали | `snapshotPart(doc, props)` | `finalShape()` | из истории операций (`modeling::NamedShape`) | из `ModelLink::properties` (у документа детали свойств нет); масса = объём BRepGProp · плотность |
| Документ сборки | `snapshotAssembly(shared_ptr<doc>)` | компаунд `placedParts()` (подавленные вхождения не входят) | только сигнатуры | свойства корневого определения; масса — `flatBom().totalMass` |
| Файл | `fileModelLoader(baseDir)` | `PartDocument::fromJson(partRegistry())` / `AssemblyDocument::loadFile` | | |

Для сборки снимок хранит `edgeOwner` — определение детали для каждого ребра компаунда
(рёбра формы детали развёртки ищутся в `TopologyIndex` компаунда); по нему ставятся позиции.
`elementReference(snapshot, kind, index)` даёт ссылку (имя + сигнатура) для определения
размеров.

## Листы, виды, аннотации

`SheetDef`: формат ГОСТ 2.301 (`SheetFormat {base, multiplier, orientation}`), масштаб листа
(пусто — наибольший помещающийся из ряда ГОСТ 2.302 не больше `DrawingSettings::maxScale`),
графы основной надписи, не связанные с моделью (`TitleFields`), виды, размеры, знаки
шероховатости, знак «остальное», технические требования, перечень ISO 7573.

| `ViewKind` | Ориентация | Положение | Стандарт |
|---|---|---|---|
| `Base` | `toward`/`right` | центр проекционной группы — `position` или центр области | ГОСТ 2.305, разд. 5 (главный вид) |
| `Projected` | `projectedFrame(parent, side, метод)` | проекционная связь с `parent` (`alignedAnchor`, зазор `viewGap`) | ГОСТ 2.305, разд. 5; метод первого угла ЕСКД / третьего ISO 128-30 |
| `Axonometric` | `axonometricFrame(parent)`, изометрия/диметрия | вне связи; приведённые коэффициенты (`reducedAxonometry`) | ГОСТ 2.317-2011, пп. 5.1, 5.2 |
| `Section` | с `side` — как проекционный вид; без `side` — `toward`/`right` | в связи или вне её | ГОСТ 2.305, разд. 6, 7: плоскость через `planePoint`, взгляд −toward; обозначение на `markView`, надпись «А–А» (масштаб в скобках, если отличается) |
| `Detail` | как у `parent` | вне связи; масштаб по умолчанию — ближайший ряда ГОСТ 2.302 не меньше 2× листа | ГОСТ 2.305, разд. 8: окружность на `parent`, надпись «Б (4:1)» |

Буквы обозначений без явного `letter` назначаются по порядку по всему чертежу
(`designationLetter`, ГОСТ 2.316 — без Ё, З, Й, О, Х, Ъ, Ы, Ь), явные буквы пропускаются.

Проверка определений (`validate`, вызывается при обновлении и загрузке): ровно один главный
вид на листе; родитель и вид обозначения разреза объявлены раньше и ортогональны (не
аксонометрия и не выносной элемент); вид в проекционной связи имеет родителя в группе;
уникальные идентификаторы; вид размера существует; `s` = 0,5…1,4 мм (ГОСТ 2.303).

Аннотации:

- `DimensionItem {id, view, def, lastValue}` — `annotations::DimensionDef`; ссылки точек
  привязки — `ModelRef::persistent` (имя + сигнатура), индекс вычисляется при обновлении.
  Все типы и оформление — `ANNOTATIONS.md` (ГОСТ 2.307, ISO 129-1, допуски ISO 286).
- `RoughnessItem {id, view, edge, at, spec}` — знак ГОСТ 2.309 на изображении ребра модели:
  самый длинный видимый прямолинейный участок ребра на виде, вершина знака — в доле `at`
  длины, знак — снаружи (сторона от центра габарита вида). Если параметр знака читался бы
  «вверх ногами» (линия обращена наружу вниз), знак ставится на полке линии-выноски со
  стрелкой на поверхности (ГОСТ 2.309, ГОСТ 2.316).
- Резьба (ГОСТ 2.311, `ANNOTATIONS.md`, «Резьба»): `ViewDef::threads` (по умолчанию `true`) —
  условная резьба модели (`modeling::threadsOf`) на основных, проекционных видах и разрезах
  (`ComputedView::threads`); `ThreadNoteItem {id, view, face, def}` — размер резьбы с
  обозначением «M10×1,25LH-6H» (`def.toleranceField`, `offset`, `leaderAngleDeg`, `textShift`),
  ссылка `face` — грань резьбы (имя + сигнатура, следует за элементом); грань не найдена, не
  резьба или резьба не на виде — висячий размер в `UpdateReport::dangling`
  (`ComputedSheet::threadNotes`).
- `roughnessRemainder` — знак в правом верхнем углу (ГОСТ 2.309, изм. 2002);
  `technicalRequirements` — над основной надписью (ГОСТ 2.316, пункты нумеруются).

Основная надпись (ГОСТ 2.104-2006): первый лист — форма 1, последующие — форма 2а. Графы 1, 2,
3, 5 берутся из модели, если не заданы в `TitleFields`; у сборочного чертежа к обозначению
добавляется код «СБ» (ГОСТ 2.102), материал не пишется; масса — в килограммах без единицы
(3 знака до 1 кг, 2 — до 100 кг); графа 6 — масштаб листа (`ScaleRatio::label`), 7/8 — номер
листа и число листов чертежа.

## Компоновка

Области листа (мм): рамка с полями 20/5, основная надпись 185×55 в правом нижнем углу,
над ней — технические требования (высота по переносу строк, шаг 1,7h) и перечень ISO 7573;
знак «остальное» резервирует 25 мм сверху.

- Широкий лист (от рамки до основной надписи ≥ 150 мм, т. е. альбомные А3 и больше): группа
  видов в проекционной связи — слева от основной надписи на всю высоту; виды вне связи —
  колонкой над техническими требованиями.
- Узкий лист (А4 книжный и т. п.): общая область над техническими требованиями, группа —
  левые 60 %, виды вне связи — правые 40 %.

Масштаб группы — наибольший из ряда, при котором габарит группы (с зазорами `viewGap` и местом
под надписи разрезов) помещается в область; явный масштаб, который не помещается, — замечание в
отчёте. Виды вне связи делят свою область поровну по высоте; каждый — в своём масштабе
(по умолчанию масштаб листа) или в наибольшем помещающемся, не больше желаемого.

Размеры не участвуют в компоновке: их положение задаёт `offset`, место для них — зазор между
видами (`viewGap` = 30 мм по умолчанию) и отступ `margin` от рамки.

## Обновление

`update(snapshot, cache, spec)`:

1. Сравнение хэша формы с `resultHash` → `modelChanged`, рост ревизии.
2. Ориентации видов; HLR основных, проекционных и аксонометрических видов — запросы
   `views::ViewCache` сразу для всех видов листа (рабочие потоки, ключ — содержимое формы и
   параметры вида); разрезы — `sectionShape` с кэшем документа (ключ — хэш формы, параметры
   вида, точка плоскости, вид разреза; до 64 записей); выносные элементы — отсечение вида
   родителя. `viewsComputed`/`viewsFromCache` — по статистике кэшей.
3. Компоновка, масштабы, надписи, осевые линии и центровые метки (`findCenterGeometry`; у
   разреза — по оставшейся части модели). Секущая плоскость должна давать след на виде
   обозначения, иначе ошибка.
4. Размеры: каждая ссылка переводится на новую форму `annotations::rebindRef` (имя → история
   → сигнатура); при успехе сохранённое имя и сигнатура обновляются («следуют» за элементом),
   размер пересчитывается из геометрии вида. Сломанная ссылка или элемент, не изображённый на
   виде, — размер висячий, не выводится, причина — в `UpdateReport::dangling`. Значение,
   отличающееся от `lastValue` больше 1e-9, — в `UpdateReport::stale` («S1/A: 60 → 80»);
   `DimensionReport::method` — худший способ разрешения ссылок размера.
5. Знаки шероховатости — так же (висячий знак не выводится).
6. Позиции (`ViewDef::autoBalloons`, только сборка): для каждой составной части спецификации
   (`spec`, иначе спецификация по умолчанию из BOM) — самая длинная видимая линия её
   изображения на виде (`edgeOwner`), точка выноски — середина линии; полки — колонной справа
   от вида (слева, если справа нет места) сверху вниз в порядке точек, шаг ≥ 10 мм
   (ГОСТ 2.109); номера — `synchronizeBalloons` по спецификации. Части, не видимые на виде, —
   `BalloonReport::withoutBalloon`.
7. Основная надпись.

`checkModel(snapshot)` — без обновления: изменилась ли модель, какие виды и размеры будут
пересчитаны. `render(font)` — листы `Drawing` (виды, штриховка, осевые, обозначения, размеры,
знаки, позиции, технические требования, перечень). Тот же шрифт следует задать для обновления
(`setFont`) — ширины текстов определяют геометрию размеров и полок.

## Спецификация — отдельный документ

`SpecificationDocument` — свой файл (`"format": "bendcore-specification"`, версия 1): ссылка на
сборку, `SpecificationSettings` (форматы, примечания, разделы по ключу «обозначение или
наименование» составной части — устойчиво при перезагрузке сборки; документы раздела
«Документация», сборочный чертёж и его формат, резерв позиций), графы основной надписи.
`update(snapshot)` строит состав `buildSpecification` (ГОСТ 2.106, `SPECIFICATION.md`) и
возвращает, изменился ли он; `specification()` передаётся в `DrawingDocument::update`, чтобы
номера позиций на чертеже совпали со спецификацией. `render(font)` — листы формы 1 (А4,
основная надпись форм 2 и 2а).

## Формат файла

JSON, `"format": "bendcore-drawing"`, `"version": 2` (`DrawingDocument::kFormatVersion`):

```json
{"format": "bendcore-drawing", "version": 2,
 "model": {"kind": "part", "path": "bracket.json", "resultHash": "9f3c…", "revision": 2,
           "properties": {"designation": "РД.10.001", "name": "Кронштейн", "material": "Сталь 20", "density": 7850}},
 "settings": {"lineThickness": 0.5, "projection": "firstAngle", "viewGap": 30, "margin": 15,
              "maxScale": [5, 1], "reducedAxonometry": true},
 "sheets": [{"id": "S1", "format": {"base": "A3", "multiplier": 1, "orientation": "landscape"},
   "scale": null, "title": {"organization": "bendcore", "developer": {"surname": "Иванов", "date": "11.26"}, …},
   "views": [{"id": "F", "kind": "base", "toward": [0, -1, 0], "right": [1, 0, 0], …},
             {"id": "S", "kind": "section", "planePoint": [40, 0, 0], "markView": "F", "sectionKind": "cut", …}],
   "dimensions": [{"id": "A", "view": "F", "type": "horizontal", "offset": -24,
     "anchors": [{"anchor": "point", "ref": {"name": "V(…)", "kind": "vertex", "signature": {…}}}, …],
     "tolerance": null, "lastValue": 80}],
   "roughness": [{"id": "Ra1", "view": "F", "edge": {…}, "at": 0.8, "spec": {"method": "materialRemoval", "value": "3,2"}}],
   "threadNotes": [{"id": "TH1", "view": "S", "face": {"name": "Tap:Wall", "kind": "face", "signature": {…}},
     "offset": 10, "toleranceField": "6H", "leaderAngleDeg": 45, "textShift": 0}],
   "roughnessRemainder": {"method": "materialRemoval", "value": "6,3"},
   "technicalRequirements": ["Острые кромки притупить."], "partsList": false}]}
```

Масштабы — пары `[num, den]` только из ряда ГОСТ 2.302 (иначе `ParseError`). Вычисленное
состояние (виды, геометрия размеров) не сохраняется — после загрузки нужен `update`; хэш
модели и последние значения размеров сохраняются, поэтому первое обновление после загрузки
сообщает об изменениях модели и размеров с прошлого сеанса.

**Миграция v1 → v2** (версия 1 — первоначальная схема): модель — строка пути в `"model"` и вид
в `"modelKind"` (хэш — `"modelHash"`); формат листа — строка `«A3L»`, `«A4x3P»` (основной формат,
кратность, ориентация L/P); масштаб вида — число (коэффициент, должен быть в ряду ГОСТ 2.302);
ссылки размеров и знаков — только имя элемента (`"ref"`, `"refKind"`; у знака — `"edge"`),
без сигнатуры: такие ссылки разрешаются по имени, после первого обновления получают
сигнатуру. Сохранение — всегда версия 2. Ошибки: не JSON, чужой формат, нет обязательных полей,
неизвестные значения перечислений, нарушение `validate` → `ParseError`; версия новее → `Unsupported`.

## Экспорт комплекта

`exportKit(drawing, specification, {directory, baseName, font})`:

- `<base>.pdf` — один многостраничный PDF: листы чертежа, затем листы спецификации (размер
  страницы — по листу, шрифт встраивается один раз; `EXPORT.md`);
- `<base>_<лист>.dxf` и `.svg` на каждый лист чертежа, `<base>_SP<n>.dxf/.svg` — на каждый лист
  спецификации.

Примеры (`docs/drawing/examples/`, получены тестами): `assembly_unit.pdf` — сборочный чертёж
узла «вал + втулка + крепёж» (А3) и спецификация (А4); `bracket_a3.png` — превью 100 dpi
рабочего чертежа кронштейна после изменения длины полки A = 80 (PDF с встроенным шрифтом —
около 0,8 МБ).

## Ограничения

- Компоновка не учитывает размеры и выноски: их размещение без пересечений — забота
  `offset`/`textShift` (автокомпоновка размеров не реализована, см. `ANNOTATIONS.md`).
- Позиции ставятся на середину самой длинной видимой линии детали (точка выноски на контуре, а
  не внутри); линии-выноски соседних позиций могут пересекаться — порядок полок по высоте точек
  уменьшает, но не исключает пересечения.
- Разрез сборки штрихуется одинаково для всех деталей (ГОСТ 2.306 требует разного направления
  или шага у смежных деталей), условности ГОСТ 2.305 разд. 9 / ГОСТ 2.109 (валы, крепёж в
  продольном разрезе не рассекаются) не применяются — в тестах сборочный чертёж без разреза.
- Свойства детали (обозначение, материал, плотность) хранятся в документе чертежа: в формате
  документа детали их нет.
- Основная надпись — одна строка наименования (без «Сборочный чертёж» второй строкой).
- Документ сборки: ссылки размеров — только по сигнатуре (у компаунда нет истории операций).
- Кэш разрезов и `ViewCache` — в памяти процесса.

## Как тестировать

```bash
cmake --build build-occt --target test_drawing_document
ctest --test-dir build-occt -R drawing_document --output-on-failure
```

Файлы — `build-occt/drawing_document_out/`. Тесты `tests/drawing_v2/test_drawing_document_*.cpp`:

- `parts` — эталонные детали 1–3 `docs/modeling/REFERENCE_PARTS.md` (кронштейн, вал со
  шпоночным пазом, фланец; построение — как в `test_modeling_document_reference_parts`):
  вид спереди, сверху, слева, изометрия, разрез/сечение А–А, 4–6 размеров, шероховатость,
  «остальное», технические требования. Значения размеров — против параметров модели (A = 60,
  ⌀8, L = 100, ⌀30, ⌀120 …); в DXF — текст числа и размерная линия длиной значение · масштаб;
  виды в проекционной связи (совпадение координат привязки), в рамке; объём кронштейна — против
  формулы, масса в основной надписи = объём · 7850; DXF — `$LIMMAX` = формат листа, ezdxf
  (AC1015, `audit()` без ошибок, `$INSUNITS = 4`, кириллица обозначения); PDF — `pdfinfo`
  (1 страница, «A3»/«A2»), `pdftotext` (обозначение, наименование, материал, «А–А», технические
  требования, фамилия, масса). Повторное обновление — 5 видов из кэша, 0 расчётов; изменение
  параметра (A = 80 и d = 10; L = 120; D = 140) → ревизия 2, 5 видов пересчитаны, ссылки не
  сломаны, новые значения в DXF, отчёт `stale` («S1/A: 60 → 80»).
- `assembly` — узел: вал (документ детали), втулка фланцевая (документ детали: диск, ступица,
  отверстие + круговой массив 4), 4 пакета «болт М10×30 ГОСТ 7798 — шайба ГОСТ 11371 — шайба —
  гайка ГОСТ 5915» (`insertFastenerStacks`). Спецификация: «ВТ.01.000 СБ» без позиции, детали 1,
  2, стандартные изделия 3–5 с количествами 4, 4, 8; позиции на виде спереди — 5 выносок,
  номера = спецификации, точка каждой — на видимой линии своей детали, полки в колонну с шагом
  ≥ 10; масса = Σ объём · плотность; комплект — PDF 2 страницы (`pdfinfo`: А3 и А4), 5 файлов,
  тексты (`pdftotext`, DXF, ezdxf); вал подавлен → спецификация и позиции перенумерованы (4
  выноски).
