# Документ чертежа (`bendcore_drawing_document`)

Фаза 4 `docs/ROADMAP_GENERAL_CAD.md` — сквозной результат: документ детали или сборки →
документ чертежа → комплект PDF/DXF/SVG. Модуль связывает построители видов
(`VIEWS.md`), размеры и аннотации (`ANNOTATIONS.md`), спецификацию (`SPECIFICATION.md`),
модель листа и экспорт (`DRAWING_MODEL.md`, `EXPORT.md`).

- Заголовок: `include/bendcore/drawing_v2/drawing_document.hpp`, пространство имён
  `bendcore::drawing_v2::document`.
- Исходники: `src/drawing_v2/document/` — `model_snapshot.cpp` (снимки модели, загрузка по
  пути), `drawing_document.cpp` (проверка, обновление, компоновка, вывод листов),
  `serialization.cpp` (формат файла, миграция), `specification_document.cpp` (спецификация,
  экспорт комплекта).
- Сборка: `cmake/drawing_document.cmake`, цель `bendcore_drawing_document` (зависит от
  `bendcore_drawing_annotations`; только при `BENDCORE_WITH_OCCT=ON`). nlohmann/json (MIT) —
  только для формата файла.
- Ошибки — `Result`/`Status` с кодом; размеры и знаки, чьи элементы модели исчезли, — не
  ошибка, а «висячие» элементы в отчёте обновления.

## Модель

`ModelLink {kind, path, resultHash, revision, properties}` — ссылка документа на модель: вид
(деталь/сборка), путь к файлу документа (относительно файла чертежа), хэш формы результата
при последнем обновлении (`views::shapeContentHash`, 16 hex — тот же ключ, что у кэша видов)
и счётчик ревизий (растёт, когда при обновлении хэш изменился).

`ModelSnapshot` — состояние модели для обновления:

| Источник | Функция | Форма | Имена ссылок | Свойства основной надписи |
|---|---|---|---|---|
| Документ детали | `snapshotPart(doc, props)` | `finalShape()` | из истории операций (`modeling::NamedShape`) | из `ModelLink::properties` (у документа детали свойств нет); масса = объём BRepGProp · плотность |
| Документ сборки | `snapshotAssembly(shared_ptr<doc>)` | компаунд `placedParts()` (подавленные вхождения не входят) | только сигнатуры | свойства корневого определения; масса — `flatBom().totalMass` |
| Файл | `fileModelLoader(baseDir)` | `PartDocument::fromJson(partRegistry())` / `AssemblyDocument::loadFile` | | |

Для сборки снимок хранит `edgeOwner` — определение детали для каждого ребра компаунда
(рёбра формы детали развёртки ищутся в `TopologyIndex` компаунда); по нему ставятся позиции.
`elementReference(snapshot, kind, index)` даёт ссылку (имя + сигнатура) для определения
размеров.

## Листы, виды, аннотации

`SheetDef`: формат ГОСТ 2.301 (`SheetFormat {base, multiplier, orientation}`), масштаб листа
(пусто — наибольший помещающийся из ряда ГОСТ 2.302 не больше `DrawingSettings::maxScale`),
графы основной надписи, не связанные с моделью (`TitleFields`), виды, размеры, знаки
шероховатости, знак «остальное», технические требования, перечень ISO 7573.

| `ViewKind` | Ориентация | Положение | Стандарт |
|---|---|---|---|
| `Base` | `toward`/`right` | центр проекционной группы — `position` или центр области | ГОСТ 2.305, разд. 5 (главный вид) |
| `Projected` | `projectedFrame(parent, side, метод)` | проекционная связь с `parent` (`alignedAnchor`, зазор `viewGap`) | ГОСТ 2.305, разд. 5; метод первого угла ЕСКД / третьего ISO 128-30 |
| `Axonometric` | `axonometricFrame(parent)`, изометрия/диметрия | вне связи; приведённые коэффициенты (`reducedAxonometry`) | ГОСТ 2.317-2011, пп. 5.1, 5.2 |
| `Section` | с `side` — как проекционный вид; без `side` — `toward`/`right` | в связи или вне её | ГОСТ 2.305, разд. 6, 7: плоскость через `planePoint`, взгляд −toward; обозначение на `markView`, надпись «А–А» (масштаб в скобках, если отличается) |
| `Detail` | как у `parent` | вне связи; масштаб по умолчанию — ближайший ряда ГОСТ 2.302 не меньше 2× листа | ГОСТ 2.305, разд. 8: окружность на `parent`, надпись «Б (4:1)» |

Разрезы на видах (ГОСТ 2.305, разд. 6; `VIEWS.md`, «Общая схема разрезов»):

- `ViewDef::localSections` (только `Base`/`Projected`) — местные разрезы: `views::LocalSection
  {boundary {points, spline}, depth}`, контур в координатах этого вида (мм модели), глубина от
  ближайшей к наблюдателю точки модели. Вид с местными разрезами считается не `ViewCache`, а
  `localSectionShape` с кэшем разрезов документа (ключ — хэш формы, параметры вида, контуры,
  глубины, флаги нерассекаемых деталей); на листе — штриховка фигуры сечения и волнистая
  граница (`renderBreakLines`).
- `ViewDef::stepPoints` (`Section`) — ступенчатый разрез: ещё точки параллельных плоскостей;
  уступы — вдоль следа на `markView` (`sight × toward` вида обозначения; плоскости, параллельные
  виду обозначения, — ошибка). Обозначение — `renderSteppedPlaneMark`; след каждой плоскости
  должен быть на виде обозначения.

**Условности разрезов сборок** (ГОСТ 2.305, разд. 9; ГОСТ 2.109): `sectionParts(snapshot, sight)`
для разрезов и местных разрезов сборки делит компаунд на детали (`ModelSnapshot::childOwner` —
определение каждой дочерней формы) и отмечает нерассекаемые: `sectionRule(PartProperties,
имя)` — свойство компонента `sectionCut` (необязательное поле `"sectionCut"` свойств
определения в файле сборки, `docs/assembly/ASSEMBLY_DOCUMENT.md`), иначе по умолчанию
стандартные изделия (пустое обозначение — изделия библиотеки крепежа), болты, винты, шпильки,
гайки, шайбы, штифты, шпонки, заклёпки, валы, оси, шпиндели — нерассечёнными при продольном
разрезе (`longitudinalSection`: ось наибольшего цилиндра в плоскости), шарики — всегда. Смежные
рассечённые детали штрихуются по-разному (`hatchPatterns`). У чертежа детали — одна деталь
(многотельная деталь штрихуется одинаково).

Буквы обозначений без явного `letter` назначаются по порядку по всему чертежу
(`designationLetter`, ГОСТ 2.316 — без Ё, З, Й, О, Х, Ъ, Ы, Ь), явные буквы пропускаются.

Проверка определений (`validate`, вызывается при обновлении и загрузке): ровно один главный
вид на листе; родитель и вид обозначения разреза объявлены раньше и ортогональны (не
аксонометрия и не выносной элемент); вид в проекционной связи имеет родителя в группе;
уникальные идентификаторы; вид размера существует; `s` = 0,5…1,4 мм (ГОСТ 2.303).

Аннотации:

- `DimensionItem {id, view, def, lastValue}` — `annotations::DimensionDef`; ссылки точек
  привязки — `ModelRef::persistent` (имя + сигнатура), индекс вычисляется при обновлении.
  Все типы и оформление — `ANNOTATIONS.md` (ГОСТ 2.307, ISO 129-1, допуски ISO 286).
- `RoughnessItem {id, view, edge, at, spec}` — знак ГОСТ 2.309 на изображении ребра модели:
  самый длинный видимый прямолинейный участок ребра на виде, вершина знака — в доле `at`
  длины, знак — снаружи (сторона от центра габарита вида). Если параметр знака читался бы
  «вверх ногами» (линия обращена наружу вниз), знак ставится на полке линии-выноски со
  стрелкой на поверхности (ГОСТ 2.309, ГОСТ 2.316).
- Резьба (ГОСТ 2.311, `ANNOTATIONS.md`, «Резьба»): `ViewDef::threads` (по умолчанию `true`) —
  условная резьба модели (`modeling::threadsOf`) на основных, проекционных видах и разрезах
  (`ComputedView::threads`); `ThreadNoteItem {id, view, face, def}` — размер резьбы с
  обозначением «M10×1,25LH-6H» (`def.toleranceField`, `offset`, `leaderAngleDeg`, `textShift`),
  ссылка `face` — грань резьбы (имя + сигнатура, следует за элементом); грань не найдена, не
  резьба или резьба не на виде — висячий размер в `UpdateReport::dangling`
  (`ComputedSheet::threadNotes`).
- `roughnessRemainder` — знак в правом верхнем углу (ГОСТ 2.309, изм. 2002);
  `technicalRequirements` — над основной надписью (ГОСТ 2.316, пункты нумеруются).

Основная надпись (ГОСТ 2.104-2006): первый лист — форма 1, последующие — форма 2а. Графы 1, 2,
3, 5 берутся из модели, если не заданы в `TitleFields`; у сборочного чертежа к обозначению
добавляется код «СБ» (ГОСТ 2.102), материал не пишется; масса — в килограммах без единицы
(3 знака до 1 кг, 2 — до 100 кг); графа 6 — масштаб листа (`ScaleRatio::label`), 7/8 — номер
листа и число листов чертежа.

### Оформление листа, метод проекций, дополнительный вид

- `DrawingSettings::sheetStyle` — `Eskd` (рамка ГОСТ 2.104, формы 1 и 2а) или `Iso7200` (рамка
  ISO 5457, основная надпись ISO 7200 со знаком метода проекций ISO 5456-2 на каждом листе,
  `DRAWING_MODEL.md`); при ISO основные форматы — ISO 216 (размеры те же). Поля ISO —
  `ComputedSheet::isoTitle`: владелец — `TitleFields::organization`, обозначение, наименование,
  автор (`developer`), утвердивший (`approver`) — из граф ЕСКД; тип документа (пусто — «Чертёж
  детали» / «Сборочный чертёж», по-английски «Detail drawing» / «Assembly drawing»), статус,
  ревизия, дата выпуска, язык (пусто — «ru»), отдел — новые поля `TitleFields`. Область видов
  и проверка перекрытий учитывают рамку и надпись выбранного оформления.
- `DrawingDocument::setProjectionMethod` — метод проекций документа (`VIEWS.md`, «Метод проекций
  документа»).
- `ViewKind::Auxiliary` — дополнительный вид по стрелке с буквой (`VIEWS.md`, «Дополнительный
  вид»); `ViewDef::rotated`, `ComputedView::rotationDeg`, `ComputedView::arrow`.
- Файл (версия 2 без изменения, поля необязательные): `settings.sheetStyle` (`"iso7200"`, пишется
  только не по умолчанию), `title.documentType/documentStatus/revision/issueDate/language/department`
  (пишутся непустые), вид `"kind": "auxiliary"` и `"rotated": true`.

Тесты: `tests/drawing_v2/test_drawing_document_iso.cpp`.

## Компоновка

Области листа (мм): рамка с полями 20/5, основная надпись 185×55 в правом нижнем углу,
над ней — технические требования (высота по строкам `technicalRequirementsLines` — тот же
перенос по начертанию, что при выводе, `ANNOTATIONS.md`; шаг 1,7h) и перечень ISO 7573;
знак «остальное» резервирует 25 мм сверху.

- Широкий лист (от рамки до основной надписи ≥ 150 мм, т. е. альбомные А3 и больше): группа
  видов в проекционной связи — слева от основной надписи на всю высоту; виды вне связи —
  колонкой над техническими требованиями.
- Узкий лист (А4 книжный и т. п.): общая область над техническими требованиями, группа —
  левые 60 %, виды вне связи — правые 40 %.

Масштаб группы — наибольший из ряда, при котором габарит группы (с зазорами `viewGap` и местом
под надписи разрезов) помещается в область; явный масштаб, который не помещается, — замечание в
отчёте.

**Виды вне проекционной связи** (разрезы и сечения без `side`, выносные элементы, аксонометрия;
ГОСТ 2.305, разд. 6–8 допускает их «на любом месте поля чертежа» с обозначением):

- без `ViewDef::position` — колонкой в своей области: ячейки поровну по высоте делят только виды
  без явного положения; масштаб — заданный `ViewDef::scale` или масштаб листа (выносной элемент —
  ближайший ряда ГОСТ 2.302 не меньше 2× листа). Масштаб **без** явного значения уменьшается до
  наибольшего помещающегося в ячейку; явный масштаб не уменьшается — если вид не помещается в
  ячейку, в отчёте замечание «view 'B' at 1:1 does not fit its cell; set its position on the
  sheet»;
- с `ViewDef::position` — вид свободен: центр габарита изображения вместе с местом надписи
  (`kViewLabelRoom` = 14 мм над разрезом и выносным элементом) — в заданной точке листа,
  масштаб — заданный или масштаб листа, ячейка не ограничивает ни положение, ни масштаб.

После компоновки — проверка перекрытий (предупреждения `UpdateReport::warnings`, не ошибки):
габариты изображений с местом надписей попарно («views 'F' and 'B' overlap»), с основной
надписью («overlaps the title block») и с рамкой («goes beyond the drawing frame»); перекрытие и
выход меньше 0,5 мм не считаются. Размеры и выноски в проверке не участвуют.

Размеры не участвуют в компоновке видов: их положение задаёт `offset`, место для них — зазор между
видами (`viewGap` = 30 мм по умолчанию) и отступ `margin` от рамки. Расстановка размеров одного
вида по ГОСТ 2.307 — `DrawingDocument::arrangeDimensions(model, sheet, view, options)`
(`annotations::arrangeDimensions`, `ANNOTATIONS.md`, «Автокомпоновка размеров»): меняет `offset`,
`textShift`, `leaderAngleDeg` размеров вида по последнему обновлению; после вызова нужен `update`.

## Обновление

`update(snapshot, cache, spec)`:

1. Сравнение хэша формы с `resultHash` → `modelChanged`, рост ревизии.
2. Ориентации видов; HLR основных, проекционных и аксонометрических видов — запросы
   `views::ViewCache` сразу для всех видов листа (рабочие потоки, ключ — содержимое формы и
   параметры вида); разрезы — `sectionShape` с кэшем документа (ключ — хэш формы, параметры
   вида, точка плоскости, вид разреза; до 64 записей); выносные элементы — отсечение вида
   родителя. `viewsComputed`/`viewsFromCache` — по статистике кэшей.
3. Компоновка, масштабы, надписи, осевые линии и центровые метки (`findCenterGeometry`; у
   разреза — по оставшейся части модели). Секущая плоскость должна давать след на виде
   обозначения, иначе ошибка.
4. Размеры: каждая ссылка переводится на новую форму `annotations::rebindRef` (имя → история
   → сигнатура); при успехе сохранённое имя и сигнатура обновляются («следуют» за элементом),
   размер пересчитывается из геометрии вида. Сломанная ссылка или элемент, не изображённый на
   виде, — размер висячий, не выводится, причина — в `UpdateReport::dangling`. Значение,
   отличающееся от `lastValue` больше 1e-9, — в `UpdateReport::stale` («S1/A: 60 → 80»);
   `DimensionReport::method` — худший способ разрешения ссылок размера.
5. Знаки шероховатости — так же (висячий знак не выводится).
6. Позиции (`ViewDef::autoBalloons`, только сборка): для каждой составной части спецификации
   (`spec`, иначе спецификация по умолчанию из BOM) — самая длинная видимая линия её
   изображения на виде (`edgeOwner`), точка выноски — середина линии; полки — колонной справа
   от вида (слева, если справа нет места) сверху вниз в порядке точек, шаг ≥ 10 мм
   (ГОСТ 2.109); номера — `synchronizeBalloons` по спецификации. Части, не видимые на виде, —
   `BalloonReport::withoutBalloon`.
7. Основная надпись.

`checkModel(snapshot)` — без обновления: изменилась ли модель, какие виды и размеры будут
пересчитаны. `render(font)` — листы `Drawing` (виды, штриховка, осевые, обозначения, размеры,
знаки, позиции, технические требования, перечень). Шрифт текстов — `DrawingSettings::textFont`:
`gost2304` (по умолчанию; однолинейный шрифт типа Б ГОСТ 2.304, метрики встроены, `font` не
нужен) или `truetype` (метрики и вывод — шрифтом `font`; тот же шрифт следует задать для
обновления, `setFont`, — ширины текстов определяют геометрию размеров и полок). `EXPORT.md`,
«Шрифт ГОСТ 2.304».

## Групповой чертёж (ГОСТ 2.113)

Групповой рабочий чертёж детали способом с таблицей исполнений (ГОСТ 2.113-75, разд. 2): одно
изображение — базовое исполнение; размеры, различающиеся у исполнений, — буквами вместо чисел;
значения — в таблице исполнений на поле чертежа. Исходник `src/drawing_v2/document/group_drawing.cpp`.

- Включение — `DrawingSettings::group.enabled` (`GroupDrawingSettings {enabled, mass, material,
  headers}`); только для чертежа детали (у сборки — предупреждение, обычный чертёж).
- **Снимок всех исполнений** — `snapshotPartConfigurations(document, properties)`: копия документа
  детали (сохранение с кэшем и загрузка — исходный документ, его активное исполнение и история не
  меняются) перестраивается в каждом исполнении таблицы параметров
  (`docs/modeling/PART_DOCUMENT.md`, «Таблица параметров»); результат — снимок базового
  исполнения (первая строка) с `ModelSnapshot::configurations` (`ConfigurationSnapshot
  {designation, fullDesignation, name, material, massKg, suppressed, model}`) и операциями
  столбцов подавления (`configurationFeatures`: id, подпись). Материал исполнения — ячейка
  материала (имя и плотность из `kernel::builtInMaterials()`), иначе свойства детали. Хэш снимка —
  по формам всех исполнений: изменённая ячейка таблицы параметров — изменённая модель
  (`checkModel`, ревизия). `update(loader)` в групповом режиме просит загрузчик о всех исполнениях
  (`ModelLink::withConfigurations`, `fileModelLoader`); деталь без таблицы — обычный снимок и
  предупреждение «group drawing: the part has no configuration table».
- **Значения по исполнениям** (`computeGroup`): для каждого исполнения — обновление копии
  документа чертежа (без группового режима) по снимку исполнения: те же виды, привязки и правила
  размеров (ассоциативность сохраняется: значение — из геометрии исполнения, построенной по
  таблице параметров). Размер, выводимое число которого (по `decimals`) различается хотя бы в
  одном исполнении или которого в исполнении нет (элемент подавлен, ссылка не разрешилась),
  получает букву; у базового исполнения размер должен быть на чертеже. Совпадающие размеры
  остаются числами.
- **Буквы** — `DimensionItem::groupLetter` (задана пользователем; повтор — ошибка `InvalidInput`
  «letter 'D' … is already used»), остальные — по порядку размеров листов:
  `annotations::groupDimensionLetter` (A, B, …, без I и O). На изображении буква заменяет число
  (`DimensionDef::letter`, не сохраняется: ставится при обновлении): «A», «⌀B», допуск — только
  поле (отклонения зависят от исполнения).
- **Таблица исполнений** (`GroupDrawingResult`, `DrawingDocument::groupDrawing()`) над основной
  надписью первого листа (над перечнем ISO 7573, если он есть), правым краем к ней; технические
  требования — над таблицей; место таблицы учитывается компоновкой видов. Графы
  (`GroupColumn {key, header, defaultHeader}`):

  | Ключ | Заголовок по умолчанию | Ячейки |
  |---|---|---|
  | `designation` | Обозначение | полное обозначение исполнения (`modeling::fullDesignation`) |
  | `dim:<лист>/<размер>` | буква | значение размера в исполнении («80»; «–» — размера нет) |
  | `suppress:<операция>` | подпись операции | «есть» / «нет» (операция подавлена в исполнении); только если различается |
  | `mass` | Масса, кг | `GroupDrawingSettings::mass` и масса известна у всех исполнений; 3 знака до 1 кг, 2 — до 100 кг |
  | `material` | Материал | `GroupDrawingSettings::material` или материал различается |

  Заголовки — `GroupDrawingSettings::headers` (ключ → текст; пусто — по умолчанию). Буквенные
  графы — по алфавиту букв. Оформление таблицы — `annotations::addGroupTable` (`ANNOTATIONS.md`,
  «Таблица исполнений»).
- **Основная надпись**: обозначение и наименование — базового исполнения (первая строка таблицы
  параметров), если графы не заданы вручную; масса и материал, различающиеся у исполнений, —
  «См. табл.» (масса — если графа массы есть в таблице).
- Файл (версия 2 без изменения, поля необязательные): `settings.group {enabled, mass, material,
  headers}` (пишется только не по умолчанию), у размера — `"groupLetter"`.

Тесты: `tests/drawing_v2/test_drawing_document_group.cpp` — `PartGroupDrawingWithConfigurationTable`
(кронштейн с исполнениями РД.10.001, -01 (A = 80, d = 10), -02 (без отверстия, алюминий): буквы
ровно у A, d, hx; тексты «A», «⌀B», «C», числа 50, 8, 30; значения таблицы = ячейки таблицы
параметров, «–» и «нет» у исполнения без отверстия; масса = объём по формуле · плотность;
«См. табл.»; заголовки граф; DXF — тексты, слой TABLE до правого края основной надписи, ezdxf;
PDF — `pdftotext`; изменение таблицы параметров («-01» A = 90, «-02» с отверстием d = 12) →
таблица и буквы обновлены, hx снова число; буква вручную и повтор; файл; выключение),
`LoaderTakesConfigurationsOnlyInGroupMode` (`fileModelLoader`, деталь без таблицы).

## Спецификация — отдельный документ

`SpecificationDocument` — свой файл (`"format": "bendcore-specification"`, версия 1): ссылка на
сборку, `SpecificationSettings` (форматы, примечания, разделы по ключу «обозначение или
наименование» составной части — устойчиво при перезагрузке сборки; документы раздела
«Документация», сборочный чертёж и его формат, резерв позиций, «разборные» подсборки
`dissolved` — `"dissolvedAssemblies"`, шрифт `textFont`), графы основной надписи. Позиции
подсборок на сборочном чертеже — `SPECIFICATION.md`, «Состав из BOM».
`update(snapshot)` строит состав `buildSpecification` (ГОСТ 2.106, `SPECIFICATION.md`) и
возвращает, изменился ли он; `specification()` передаётся в `DrawingDocument::update`, чтобы
номера позиций на чертеже совпали со спецификацией. `render(font)` — листы формы 1 (А4,
основная надпись форм 2 и 2а).

Групповой режим (`SpecificationSettings::group {enabled, layout, columnHeaders}`, в файле —
`"group"`, пишется не по умолчанию): `update` строит групповую спецификацию ГОСТ 2.113 по
`assembly_v2::configurationBom` (загрузка исполнений компонентов — `setLoadOptions`), `render` —
её листы, `specification()` — спецификация активного исполнения с номерами групповой
(`SPECIFICATION.md`, «Групповая спецификация ГОСТ 2.113»).

## Отмена и повтор

`DrawingHistory` (`history.cpp`) — история правок: `record(captureEditState(doc), "название")`
перед успешной правкой (вызывающий код записывает только правки, после которых обновление
прошло), `undo(doc)` / `redo(doc)` восстанавливают `DrawingEditState {sheets, settings,
model.properties}` и возвращают название правки; после восстановления нужен `update` (если он
не удался, обратный шаг возвращает прежнее состояние). Новая правка очищает повтор, глубина —
`limit` (100 в модуле WASM), старые записи отбрасываются. Модель (параметры детали, состав
сборки) в историю не входит — её изменение приходит обновлением по модели. История не
сохраняется в файл.

## Формат файла

JSON, `"format": "bendcore-drawing"`, `"version": 2` (`DrawingDocument::kFormatVersion`):

```json
{"format": "bendcore-drawing", "version": 2,
 "model": {"kind": "part", "path": "bracket.json", "resultHash": "9f3c…", "revision": 2,
           "properties": {"designation": "РД.10.001", "name": "Кронштейн", "material": "Сталь 20", "density": 7850}},
 "settings": {"lineThickness": 0.5, "projection": "firstAngle", "viewGap": 30, "margin": 15,
              "maxScale": [5, 1], "reducedAxonometry": true, "textFont": "gost2304"},
 "sheets": [{"id": "S1", "format": {"base": "A3", "multiplier": 1, "orientation": "landscape"},
   "scale": null, "title": {"organization": "bendcore", "developer": {"surname": "Иванов", "date": "11.26"}, …},
   "views": [{"id": "F", "kind": "base", "toward": [0, -1, 0], "right": [1, 0, 0], …},
             {"id": "S", "kind": "section", "planePoint": [40, 0, 0], "markView": "F", "sectionKind": "cut", …}],
   "dimensions": [{"id": "A", "view": "F", "type": "horizontal", "offset": -24,
     "anchors": [{"anchor": "point", "ref": {"name": "V(…)", "kind": "vertex", "signature": {…}}}, …],
     "tolerance": null, "lastValue": 80}],
   "roughness": [{"id": "Ra1", "view": "F", "edge": {…}, "at": 0.8, "spec": {"method": "materialRemoval", "value": "3,2"}}],
   "threadNotes": [{"id": "TH1", "view": "S", "face": {"name": "Tap:Wall", "kind": "face", "signature": {…}},
     "offset": 10, "toleranceField": "6H", "leaderAngleDeg": 45, "textShift": 0}],
   "roughnessRemainder": {"method": "materialRemoval", "value": "6,3"},
   "technicalRequirements": ["Острые кромки притупить."], "partsList": false}]}
```

Необязательные поля вида (версия формата не меняется, прежние файлы читаются): местные разрезы
`"localSections": [{"points": [[33, 1], [47, 1], [47, 7], [33, 7]], "spline": false, "depth": 15}]`
и точки ступенчатого разреза `"stepPoints": [[35, 35, 0]]`; у свойств определения сборки —
`"sectionCut": true | false`.

Масштабы — пары `[num, den]` только из ряда ГОСТ 2.302 (иначе `ParseError`). Вычисленное
состояние (виды, геометрия размеров) не сохраняется — после загрузки нужен `update`; хэш
модели и последние значения размеров сохраняются, поэтому первое обновление после загрузки
сообщает об изменениях модели и размеров с прошлого сеанса.

**Миграция v1 → v2** (версия 1 — первоначальная схема): модель — строка пути в `"model"` и вид
в `"modelKind"` (хэш — `"modelHash"`); формат листа — строка `«A3L»`, `«A4x3P»` (основной формат,
кратность, ориентация L/P); масштаб вида — число (коэффициент, должен быть в ряду ГОСТ 2.302);
ссылки размеров и знаков — только имя элемента (`"ref"`, `"refKind"`; у знака — `"edge"`),
без сигнатуры: такие ссылки разрешаются по имени, после первого обновления получают
сигнатуру. Сохранение — всегда версия 2. Ошибки: не JSON, чужой формат, нет обязательных полей,
неизвестные значения перечислений, нарушение `validate` → `ParseError`; версия новее → `Unsupported`.

## Экспорт комплекта

`exportKit(drawing, specification, {directory, baseName, font})` (`font` обязателен только
при шрифте `truetype`; при шрифте ГОСТ он даёт невидимый текстовый слой PDF):

- `<base>.pdf` — один многостраничный PDF: листы чертежа, затем листы спецификации (размер
  страницы — по листу, шрифт встраивается один раз; `EXPORT.md`);
- `<base>_<лист>.dxf` и `.svg` на каждый лист чертежа, `<base>_SP<n>.dxf/.svg` — на каждый лист
  спецификации.

Примеры (`docs/drawing/examples/`, получены тестами): `assembly_unit_gost2304.png` — тот же
сборочный чертёж шрифтом ГОСТ 2.304 (120 dpi, `unit.pdf` теста `test_drawing_document_assembly`);
`assembly_unit.pdf` — сборочный чертёж
узла «вал + втулка + крепёж» (А3) и спецификация (А4); `bracket_a3.png` — превью 100 dpi
рабочего чертежа кронштейна после изменения длины полки A = 80 (PDF: линии шрифта ГОСТ и
невидимый слой DejaVu Sans, встроенный целиком, — около 1 МБ).

## Ограничения

- Компоновка видов не учитывает размеры и выноски; автокомпоновка размеров — по запросу и в
  пределах одного вида (размеры соседних видов и позиции в ней не учитываются); полки позиций
  автоматически не разводятся.
- Свободное положение вида не проверяется на попадание в поле технических требований и знака
  «остальное» — только перекрытие с видами, основной надписью и рамкой.
- Позиции ставятся на середину самой длинной видимой линии детали (точка выноски на контуре, а
  не внутри); линии-выноски соседних позиций могут пересекаться — порядок полок по высоте точек
  уменьшает, но не исключает пересечения.
- Условности разрезов сборок — по наименованию/обозначению детали или свойству компонента
  `sectionCut`; детали подсборки — части её компаунда по развёртке (правило берётся у детали, а
  не у подсборки). Тонкие стенки и рёбра жёсткости в разрезе штрихуются (ГОСТ 2.305 разд. 9
  требует не штриховать).
- Свойства детали (обозначение, материал, плотность) хранятся в документе чертежа: в формате
  документа детали их нет.
- Основная надпись — одна строка наименования (без «Сборочный чертёж» второй строкой).
- Документ сборки: ссылки размеров — только по сигнатуре (у компаунда нет истории операций).
- Кэш разрезов и `ViewCache` — в памяти процесса.
- Групповой чертёж — только способ с таблицей исполнений и только для детали (групповой
  сборочный чертёж — нет); изображение одно (базового исполнения): элементы, которых нет в
  базовом исполнении, не изображаются; значения отклонений размеров с буквой в таблицу не
  выводятся. Каждое обновление в групповом режиме пересчитывает чертёж по каждому исполнению
  (виды — из кэша, если формы исполнений не менялись).
