# Виды, разрезы и осевые линии по модели (`bendcore_drawing_views`)

Фаза 4, пп. 2–4 (и основа п. 5 — привязка 2D-рёбер к модели) `docs/ROADMAP_GENERAL_CAD.md`.
Библиотека строит изображения детали (OCCT `TopoDS_Shape`) и выводит их в модель листа
`bendcore_drawing_v2` (`DRAWING_MODEL.md`), откуда они экспортируются в DXF/SVG/PDF
(`EXPORT.md`).

- Заголовки: `include/bendcore/drawing_v2/views.hpp` (ориентация видов, HLR),
  `sections.hpp` (разрезы, сечения, выносные элементы), `view_sheet.hpp` (масштабы,
  компоновка, вывод на лист, осевые линии, обозначения). Пространство имён
  `bendcore::drawing_v2::views`.
- Исходники: `src/drawing_v2/views/`; сборка — `cmake/drawing_views.cmake` (цель
  `bendcore_drawing_views`, зависит от `bendcore_drawing_v2` и `bendcore_kernel`, только при
  `BENDCORE_WITH_OCCT=ON`).
- Ошибки — `Result`/`Status` с кодом (`InvalidInput`, `OperationFailed`); исключения OCCT
  перехватываются и превращаются в `OperationFailed`.

## Системы координат

Вид задаётся `ViewFrame {toward, right}`: `toward` — от модели к наблюдателю, `right` — ось x
вида, `up = toward × right` — ось y. Точка модели P на виде: `(P·right, P·up)` в мм модели
(начало вида — проекция начала координат модели). На лист: `SheetView::toSheet(p) =
anchor + scale·p`. Два вида, у которых общая ось (вид спереди и сверху — `right`, спереди и
слева — `up`), выравниваются равенством соответствующей координаты `anchor`, поэтому
проекционная связь — это одна координата точки привязки.

Главный вид по умолчанию (`defaultFrontFrame`) — вид спереди: наблюдатель со стороны −Y,
X вправо, Z вверх.

## API

```cpp
#include <bendcore/drawing_v2/view_sheet.hpp>
using namespace bendcore::drawing_v2;
using namespace bendcore::drawing_v2::views;

kernel::Shape part = ...;
const ViewFrame front = defaultFrontFrame();
const ViewFrame top   = standardFrame(front, StandardView::Top);
auto fv = projectShape(part, front);                       // HlrMethod::Exact
auto tv = projectShape(part, top, {.method = HlrMethod::Polygonal});
auto iso = projectShape(part, axonometricFrame(front, Axonometry::Isometric));

// Разрез А–А на месте главного вида: плоскость y = 20, взгляд вдоль +Y.
CuttingPlane plane{{0, 20, 0}, {0, 1, 0}};
auto sec = sectionShape(part, front, plane, SectionKind::Cut, {.hidden = false});

// Компоновка в проекционной связи, масштаб ГОСТ 2.302.
auto lay = layoutViews({{&sec.value().view, -1, SheetSide::Below},
                        {&tv.value(), 0, *standardPlacement(StandardView::Top, ProjectionMethod::FirstAngle)}},
                       area, /*gap*/ 25);
SheetView S{sec.value().view, lay.value().scale.value(), lay.value().anchors[0]};
SheetView T{tv.value(), lay.value().scale.value(), lay.value().anchors[1]};
renderView(drawing, S);
renderSectionHatch(drawing, S, sec.value());
renderView(drawing, T);
renderCenterLines(drawing, T, findCenterGeometry(part, top).value());
renderCenterLines(drawing, S, findCenterGeometry(sec.value().remaining, front).value());
renderCuttingPlaneMark(drawing, T, plane, designationLetter(0));
renderViewLabel(drawing, S, "А–А");
```

### Результат HLR (`ProjectedView`)

`edges` — `ViewEdge {curve, visibility, cls, edgeIndex, faceIndex}`:

- `curve` — `LineSeg`, `Arc`, `Circle` или `Polyline` в координатах вида. Отрезок — для прямых;
  дуга/окружность — для окружности, ось которой параллельна направлению взгляда; иначе
  (эллипс, сплайн, окружность под углом) — ломаная с прогибом `HlrOptions::curveDeflection`
  (0,01 мм модели); ломаная, лежащая на прямой, заменяется отрезком (окружность, видимая
  ребром).
- `visibility` — `Visible` / `Hidden`; `cls` — `Sharp` (ребро излома), `Smooth` (ребро между
  гранями с непрерывной касательной — линия перехода), `Silhouette` (очерк криволинейной
  грани), `SectionCut` (контур фигуры сечения).
- `edgeIndex` / `faceIndex` — индексы `kernel::TopologyIndex` **исходной** формы: у рёбер —
  ребро модели (для участка ребра, разбитого HLR, — исходное ребро), у очерка — грань, на
  которой он построен. Для разреза индексы переводятся через историю `BRepAlgoAPI_Cut`
  (`Modified`); линия пересечения грани с секущей плоскостью получает индекс этой грани
  (`Generated`). Это основа ассоциативных размеров (п. 5): ссылка «2D-ребро → элемент
  модели» устойчива в пределах одной формы, а между перестроениями переводится
  топологическим именованием (`docs/modeling/TOPOLOGICAL_NAMING.md`).

`bounds` — габарит всех рёбер; `stats.milliseconds` — время OCCT (без пост-обработки),
`stats.rawPieces` — число участков до удаления совпадений.

## Алгоритмы

**Точный HLR.** `HLRBRep_Algo::Add(shape, 0 изолиний)`, `Projector(HLRAlgo_Projector(gp_Ax2(0,
toward, right)))`, `Update`, `Hide`. Вместо `HLRBRep_HLRToShape` (он теряет связь с
моделью) обходятся рёбра структуры данных `HLRBRep_Data` напрямую: для каждого ребра
`EdgeMap().FindKey(i)` даёт ребро формы с очерками, `HLRTopoBRep_Data::NewSOldS` —
исходную подформу: грань, если ребро — очерк, построенный `HLRTopoBRep_OutLiner`, или
исходное ребро, если это участок расщеплённого ребра. Класс как в `HLRToShape`: флаг
`Rg1Line` (непрерывность G1 между гранями) — линия перехода, `RgNLine` (шов замкнутой
поверхности) не выводится, кроме случая, когда `HLRBRep_FaceIterator::OutLine()` отмечает
ребро как лежащее на очерке (шов цилиндра, совпавший с очерком). Ребра, проецирующиеся в
точку (`Vertical`), пропускаются. Видимые и невидимые интервалы — `HLRAlgo_EdgeIterator`
по `EdgeData::Status()`; параметры интервалов — параметры 3D-кривой ребра
(`BRepAdaptor_Curve`), точки проецируются функцией вида (не проектором OCCT), поэтому
координаты не зависят от внутреннего масштабирования HLR.

**Быстрый HLR.** `BRepMesh_IncrementalMesh(linearDeflection = 0,1 мм, angular = 0,3 рад)`,
`HLRBRep_PolyAlgo::Load/Projector/Update`, обход `InitHide/Hide`: каждый участок —
отрезок с исходным ребром (или гранью для внутреннего очерка `intl`) и флагами
`reg1/regn/outl`, классы — как в `HLRBRep_PolyHLRToShape`. Отрезки одного ребра с общими
концами собираются в ломаные (`chainSegments`); прямая цепочка становится одним отрезком.

**Удаление совпадений** (`removeOverlaps`). Рёбра упорядочиваются: видимые раньше
невидимых; контур сечения, резкие, очерк, линии перехода; длинные раньше коротких. Из
каждого следующего отрезка вычитаются интервалы, покрытые уже принятыми отрезками на той
же прямой (допуск 10⁻⁶ габарита вида), из дуги — угловые интервалы принятых дуг той же
окружности. Так невидимые рёбра задней грани, совпадающие с контуром, исчезают, а
нижняя окружность сквозного отверстия на виде сверху не дублирует верхнюю. Поиск
кандидатов — по корзинам (угол прямой и расстояние до начала; центр и радиус окружности),
сложность ≈ O(n).

**Разрез.** Ящик 2L×2L×L (L — диагональ габарита плюс расстояние до плоскости) со стороны
наблюдателя вычитается `BRepAlgoAPI_Cut`. Фигура сечения — плоские грани результата,
нормаль которых параллельна `sight` и которые лежат в плоскости (допуск 10⁻⁶ габарита);
площадь — `BRepGProp::SurfaceProperties`, контуры — обход `BRepTools_WireExplorer`
(прямые — концами, кривые — `GCPnts_TangentialDeflection`). Рёбра, лежащие в плоскости,
получают класс `SectionCut`. Вид разреза — HLR оставшейся части. Сечение (`Slice`) — только
рёбра граней сечения, все видимые.

**След плоскости** — прямая `point + t·(sight × toward)` на виде родителя, отсечённая
габаритом вида (Лян — Барски); плоскость должна быть перпендикулярна плоскости вида.

**Выносной элемент** — рёбра вида, отсечённые окружностью: отрезки — корнями квадратного
уравнения, дуги и окружности — точками пересечения двух окружностей (сохраняются куски,
середина которых внутри), ломаные — по звеньям.

**Осевые линии.** Цилиндрические грани (`TopologyIndex`, `SurfaceType::Cylinder`) группируются
по оси и радиусу; угловой охват суммируется по `BRepTools::UVBounds`, протяжённость по
оси — объединение интервалов v. Группа с охватом ≥ π (настраивается) даёт центровую метку,
если ось параллельна направлению взгляда, и осевую линию между торцами, если
перпендикулярна. Соосные метки разных радиусов сводятся к одной (по большему радиусу),
осевые на одной прямой с перекрытием — в одну.

**Компоновка** (`layoutViews`). Для масштабов ряда ГОСТ 2.302 от большего к меньшему
дочерние виды ставятся со стороны родителя с зазором `gap` между габаритами и
выравниванием по общей оси (`alignedAnchor`); первый масштаб, при котором габарит
компоновки помещается в область, принимается, компоновка центрируется.

Выводы: на аналитических моделях (плоскости и цилиндры) точный алгоритм обычно не
медленнее быстрого — `PolyAlgo` обрабатывает десятки тысяч отрезков триангуляции

(удаление совпадений, ломаные) — единицы процентов времени точного HLR и 5–20 % быстрого.
Фоновый расчёт и кэш по версии модели (фаза 4, п. 2) в этой библиотеке не сделаны.

## Ограничения

- Не реализованы: местный разрез, ломаные и ступенчатые разрезы (несколько плоскостей),
  наложенные и вынесенные сечения с поворотом, обозначение дополнительного вида стрелкой
  с буквой (есть только ориентация вида и подпись `renderViewLabel`), условности ГОСТ 2.305
  разд. 9 (тонкие стенки и рёбра жёсткости в разрезе не штрихуются — здесь штрихуются),
  штриховка неметаллов (ГОСТ 2.306, табл. 1 — только металлы), линии обрыва вида.
- Разрез — только плоскостью, параллельной плоскости вида (`toward = −sight`), иначе
  `InvalidInput`.
- Перспективные проекции не поддерживаются (только ортогональные, как в ЕСКД).
- Эллипсы и сплайны на виде выводятся ломаными (в модели чертежа нет эллипса и сплайна).
- Стрелки обозначений — замкнутые контуры без заливки (в модели чертежа нет заливки).
- Точный HLR даёт интервалы видимости с погрешностью ~10⁻⁴ мм у окружностей, видимых
  ребром (видно на разрезе: верхняя кромка над отверстием 25,0001…34,9999); на чертеже это
  не различимо, тесты проверяют суммарную длину с допуском 10⁻³.
- `HlrMethod::Polygonal` строит триангуляцию в формах модели (как `kernel::tessellate`, см.
  `docs/kernel/KERNEL_CORE.md`) — формы, разделяющие TShape, видят новую сетку.
- Центровые метки — только для цилиндров; конусы, сферы, торы и дуги рёбер без
  цилиндрической грани (например, дуги контура плоской пластины) меток не получают.
- Вылет осевой линии подбирается под шаблон штрихов из `Drawing::lineTypeSpec`; программы,
  которые начинают шаблон DXF не с начала линии, могут закончить её промежутком.
