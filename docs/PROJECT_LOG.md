## 2026-11-12 — Принято ускорение перестроения детали и пересечений сборки

- Профиль (выборка стеков gdb): в вырезе булева операция — 5–10 %, остальное — проверки и
  интегралы по всему телу (`BRepAlgoAPI_Check` входа, повторные `BRepCheck_Analyzer`,
  `BRepGProp`); в пересечениях — масса плиты внутри `booleanOp` и расстояние по всем граням.
- Деталь: кэш фактов о формах (валидность, объём, «результат булевой — повторная проверка
  входа не нужна»), сигнатуры неизменных элементов из входа, эскизы без ссылок не зависят от
  цепочки хэшей тела. Сборка: крупная деталь режется сеткой (`BRepAlgoAPI_Splitter`), пара
  считается по кускам рядом, отбор по габаритам граней, многопоточное расстояние; новый тест
  сверяет результат с прямым расчётом по целым деталям.
- Замеры (`docs/qa/PERFORMANCE.md`): деталь из 300 операций — 48–90 → 19 с, изменение последней
  операции — 0,24 с, холостое перестроение — 0,001 с; пересечения 300 компонентов — 58–74 → 7,5 с.
  При приёмке (параллельно со сборкой OCCT): `stress_part_300` 41 с, `stress_assembly_300` 15 с.
- Проверено: 116/116, `fuzz_loaders` отдельно проходит (под нагрузкой первый запуск упал —
  нестабилен при нехватке памяти), нагрузка и производительность последовательно 9/9,
  `check_no_stubs.sh` — 0 нарушений.

Открытые задачи (ядро): в `kernel::booleanOp` одна проверка результата вместо двух и без
пересчёта массы аргумента — ещё ~60 % времени выреза; `fuzz_loaders` под нагрузкой.

  демпфирует почти свободные повороты, и на недоопределённых сборках LM не сходился за 200 итераций.
- Ранг (степени свободы) считается QR с выбором столбца, вклад сопряжений — последовательной
  ортогонализацией в порядке добавления. Избыточным считается только сопряжение без единого
  нового уравнения, частичное перекрытие (соосность + торец) — нет.
- От OCCT модуль не зависит: сущности задаются числами, связь с гранями OCCT — следующий шаг.

Следующий шаг: извлечение сущностей сопряжений из граней и рёбер `src/kernel/`, документ сборки
со ссылками на детали.
