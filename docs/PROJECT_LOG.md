# Журнал проекта bendcore CAD

Новые записи — сверху. Формат: дата, фаза, что сделано, решения, следующий шаг.

## 2026-11-07 — Фаза 0: принято лечение геометрии и булевы операции

- `bendcore_kernel_healing` (`src/kernel/healing.cpp`, `src/kernel/boolean.cpp`,
  `docs/kernel/GEOMETRY_HEALING.md`): лечение (DirectFaces, ShapeFix, малые элементы,
  перевод B-сплайнов в аналитику собственной `BRepTools_Modification` поверх
  `GeomConvert_SurfToAnaSurf`, UnifySameDomain) и булевы операции с лестницей нечёткого
  допуска и проверкой результата. 22 теста против аналитики, проверено при приёмке.
- Ограничения: поверхности вращения и выдавливания в аналитику не переводятся; невалидного
  результата точной булевой операции на OCCT 8.0.1 воспроизвести не удалось, лестница
  проверена на случае «два тела вместо одного» (`expectedSolidCount`).
- Агенты прерывались на лимите запросов API, после перезапуска продолжили с места остановки.

## 2026-11-07 — Фаза 0, п. 1: явный набор OCCT, OCCT для WASM (инженер ядра)

Сделано:
- `file(GLOB libTK*.a)` в корневом `CMakeLists.txt` заменён списком
  `BENDCORE_OCCT_TOOLKITS` из `third_party/occt_toolkits.txt` (29 тулкитов); отсутствие

- `third_party/build_occt_wasm.sh`: OCCT 8.0.1 для Emscripten только с этими тулкитами,
  пробная программа `tests/kernel/wasm/occt_size_probe.cpp` (STEP из памяти, BRepMesh)
  проходит под node. `.wasm` пробной программы: 15,9 МБ / 4,6 МБ gzip (`-Oz`).
- `docs/kernel/OCCT_BUILD.md`.

Решения:
- К списку плана добавлены TKVCAF, TKV3d, TKService: их требует TKXCAF в OCCT 8.0.1
  (символы указаны в документе).
- Один файл списка для native и WASM, чтобы наборы не расходились.
- Исключения `-fexceptions`, как у существующей цели `bendcore_wasm`.

Следующий шаг: job CI для WASM-сборки OCCT (инженер качества, описание в
`docs/kernel/OCCT_BUILD.md`, раздел 4); перевод `build_occt.sh` на тот же список.

## 2026-11-06 — Фаза 0 запущена

Сделано:
- План `docs/ROADMAP_GENERAL_CAD.md` по результатам аудита исходников: твердотельное
  моделирование, решатель сборок, виды и экспорт чертежей — заглушки; работают эскиз

- Регламент `docs/PROJECT_PROCESS.md`: роли, правило «никаких заглушек», критерии готовности,
  владение файлами.
- Определения ролевых агентов в `.claude/agents/`.
- Точки подключения модулей `cmake/<модуль>.cmake` в корневом `CMakeLists.txt`
  (внутри `BENDCORE_WITH_OCCT`).

Решения:
- Новые подсистемы пишутся в новых каталогах (`src/kernel`, `src/modeling`,
  `src/assembly_v2`, `src/drawing_v2`), заглушки старых каталогов удаляются, а не
  дорабатываются.
- Ядро строится только в конфигурации с OCCT (`BENDCORE_WITH_OCCT=ON`).

Задачи фазы 0 в работе (параллельно):
1. Явный набор модулей OCCT вместо `file(GLOB libTK*.a)`; скрипт сборки OCCT для WASM.
2. `bendcore_kernel`: форма, сериализация BRep, тесселяция с привязкой к граням.
3. `bendcore_kernel_healing`: лечение геометрии, устойчивые булевы операции.
4. Удаление заглушек геометрии и экспорта чертежей.
5. `scripts/check_no_stubs.sh`, корпус STEP, регрессия импорта, CI.
