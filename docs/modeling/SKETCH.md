# Эскиз: геометрия, ограничения, диагностика, инструменты

Раздел 2.1 `docs/ROADMAP_GENERAL_CAD.md` (строка «Эскиз»). Три слоя:

| Слой | Где | Что делает |
|---|---|---|
| Решатель `sketch2d::Sketch` | `include/bendcore/sketch2d.hpp`, `src/sketch2d.cpp` (цель `bendcore_sketch2d`, без OCCT, собирается и в WASM) | точки и кривые, ограничения и размеры, решение и диагностика PlaneGCS |
| Сущности профиля `BoundSketch` | `include/bendcore/modeling/sketch_profile.hpp`, `src/modeling/sketch/bound_sketch.cpp` | номера сущностей 1, 2, 3…, кривые `SketchCurve` для профиля (`SKETCH_PROFILE.md`) |
| Инструменты | `include/bendcore/modeling/sketch_tools.hpp`, `src/modeling/sketch/sketch_tools.cpp` | обрезка, удлинение, эквидистанта, зеркало, массивы, скругление и фаска угла |

Узел `Sketch` документа детали строит `BoundSketch` из `SketchData` (`PART_DOCUMENT.md`).

## Сущности

| Вид (`GeoKind`) | Создание | Параметры решателя | Степени свободы |
|---|---|---|---|
| точка | `add_point(x, y)` | x, y | 2 |
| отрезок | `add_line(a, b)` | концы — точки | 4 |
| окружность | `add_circle(center, r)` | центр, радиус | 3 |
| дуга | `add_arc(center, start, end, ccw)` | центр, начало, конец, радиус, два угла; `ArcRules` связывает концы с окружностью | 5 |
| эллипс | `add_ellipse(center, focus, b)` | центр, фокус (точки эскиза; фокус задаёт направление большой оси), малая полуось | 5 |
| дуга эллипса | `add_ellipse_arc(center, focus, b, start, end, ccw)` | + концы и два параметра, `ArcOfEllipseRules` | 7 |
| B-сплайн | `add_bspline(BSplineData)` | полюса — точки эскиза; узлы, кратности и веса постоянны | 2 × полюсов |

- Дуга — нативная дуга PlaneGCS (`GCS::Arc`), а не «окружность + две точки на окружности»
  (прежний способ давал ту же геометрию, но лишние ограничения в диагностике). Дуга по часовой
  стрелке передаётся PlaneGCS как дуга против часовой с переставленными концами.
- Большая полуось эллипса `a = sqrt(|F − C|² + b²)`. Параметр точки на эллипсе
  (`ellipse_parameter`) — угол в системе (U — к фокусу, V — U, повёрнутая на +90°), как у
  `EllipticalArc2d`.
- Непериодический сплайн обязан быть зажатым (кратность крайних узлов = степень + 1): его
  концы — первый и последний полюса, поэтому «совпадение» с концом сплайна — совпадение с
  полюсом, а касательная в конце направлена к соседнему полюсу. Неверные данные сплайна —
  `std::invalid_argument` с причиной.
- Вспомогательная геометрия: `set_construction(geo, true)`; в профиль не входит
  (`BoundSketch::curves()` переносит признак в `SketchCurve::construction`).
- Удаление: `remove(geo)` помечает элемент удалённым и удаляет ссылающиеся на него
  ограничения; номера не переиспользуются. Точку, занятую живой кривой, удалить нельзя.
- Ссылка на элемент — `Geo{kind, id}` (`line_geo(id)`, `arc_geo(id)` и т. д.); номера ведутся
  отдельно для каждого вида.

## Ограничения и размеры

Номер ограничения (≥ 1) — его `tag` в PlaneGCS, по нему приходят конфликты и избыточность.

| `ConstraintKind` | Функция | Реализация PlaneGCS |
|---|---|---|
| Coincident | `constrain_coincident(p, q)` | `P2PCoincident` |
| Horizontal / Vertical | `constrain_horizontal/vertical(p, q)` | по двум точкам |
| Parallel / Perpendicular | `constrain_parallel/perpendicular(l1, l2)` | по отрезкам |
| Tangent | `constrain_tangent(a, b)` | см. ниже |
| Equal | `constrain_equal(a, b)` | отрезки — `EqualLength`; окружности/дуги — равенство радиусов; эллипсы — `EqualRadii` |
| Symmetric | `constrain_symmetric(p, q, line)` / `constrain_symmetric_point(p, q, c)` | `P2PSymmetric` |
| Midpoint | `constrain_midpoint(p, line \| arc)` | отрезок — симметрия концов относительно p; дуга — точка на окружности + на серединном перпендикуляре хорды |
| PointOn | `constrain_point_on(p, curve)` | прямая (бесконечная), окружность/дуга (окружность), эллипс/дуга эллипса (эллипс) |
| Concentric | `constrain_concentric(a, b)` | совпадение центров |
| Fix | `constrain_fix(p)` | `CoordinateX/Y` с номером (в отличие от служебного `fix_point`) |
| Rotation | `constrain_rotation(p, q, c, deg)` | собственное ограничение: q = c + R(deg)(p − c), две линейные строки (круговой массив) |
| Distance | `constrain_distance(p, q, d)`, `constrain_length(line, d)` | `P2PDistance` |
| DistanceX / DistanceY | `constrain_distance_x/y(p, q, d)` | `Difference`: q.x − p.x = d (со знаком) |
| PointCurveDistance | `constrain_point_curve_distance(p, curve, d)` | прямая — `P2LDistance` (сторона по текущему положению), окружность/дуга — `P2CDistance` |
| Radius / Diameter | `constrain_radius_of(g, r)`, `constrain_diameter(g, d)` | `CircleRadius/ArcRadius`, `…Diameter` |
| Angle | `constrain_angle(l1, l2, deg)` | `L2LAngle`, угол от l1 к l2 |
| ArcLength | `constrain_arc_length(arc, L)` | `ArcLength` |
| MajorRadius / MinorRadius | `constrain_major/minor_radius(e, v)` | собственное ограничение sqrt(\|F − C\|² + b²) = a; `Equal(b, v)` |

Прежние функции (`constrain_point_on_line`, `constrain_point_on_circle`,
`constrain_equal_length`, `constrain_equal_radius`, `constrain_radius`) сохранены и сводятся к
общим видам; их номера и поведение прежние (WASM-привязки не менялись).

**Касание.** Если у кривых есть общий конец — одна и та же точка или точки, связанные
ограничением «совпадение» (классы совпадения строятся при каждом решении), — касание
задаётся в этом конце и не дублирует совпадение:

| Пара | Общий конец P | Без общего конца |
|---|---|---|
| отрезок AB — дуга (центр C) | AB ⊥ CP | расстояние от C до прямой = r (сторона — текущая) |
| дуга — дуга | P на прямой C₁C₂ | `TangentCircumf` (внешнее/внутреннее — по текущему положению) |
| отрезок — окружность | — | расстояние от центра до прямой = r |
| окружность/дуга — окружность/дуга | — | `TangentCircumf` |
| отрезок — эллипс/дуга эллипса | общее касание `TangentEllipseLine` | то же |
| отрезок — сплайн | соседний с P полюс на прямой AB | не поддерживается |
| дуга — сплайн | CP ⊥ (P → соседний полюс) | не поддерживается |
| сплайн — сплайн | соседние полюса и P на одной прямой | не поддерживается |

Касание двух отрезков, эллипса с эллипсом или с окружностью отклоняется при создании
(`std::invalid_argument`); касание со сплайном без общего конца — при решении
(`std::logic_error`, документ превращает её в ошибку узла).

**Справочные размеры.** `set_driving(c, false)` (только для размеров, `is_dimension`):
ограничение не передаётся решателю, `constraint_value(c)` возвращает измеренное значение
(`measure(c)`). `residual(c)` — невязка любого ограничения по текущей геометрии (мм или
радианы), используется документом для проверки сходимости.

## Диагностика

`solve()` строит систему PlaneGCS, диагностирует, решает и при успехе обновляет
координаты; затем, если конфликта нет, строит систему повторно в решённом положении и
диагностирует её — якобиан в начальном приближении бывает случайно вырожден, в решении он
описывает итоговую геометрию.

`Report`:

| Поле | Смысл |
|---|---|
| `dof` | число степеней свободы (`paramsNum − rank` якобиана) |
| `status` | `определено` / `недоопределено` / `избыточно` / `конфликт` (прежние строки) |
| `definition` | `Fully` (dof = 0, без избыточности), `Under`, `Over` (конфликт или избыточность) |
| `conflicting`, `redundant`, `partially_redundant` | номера ограничений из диагностики PlaneGCS (служебные с tag 0 не выводятся) |
| `converged` | решатель сошёлся |
| `geometry` | `GeoStatus{geo, fully_defined}` для каждой живой точки и кривой; `fully_defined(geo)` |

Определённость элемента — по «зависимым параметрам» QR-разложения PlaneGCS
(`getDependentParams`, как в FreeCAD): элемент определён, если ни один его параметр (координаты
его точек, радиус, углы дуги, малая полуось) не входит в список свободных. Для интерфейса:
определённый элемент — чёрный, недоопределённый — синий, участники `conflicting/redundant` —
красные.

## Инструменты редактирования

Функции `bendcore::modeling` над `BoundSketch` возвращают `Result<SketchEditResult>`
(`created`, `modified`, `removed` — сущности; `points`, `constraints` — новые точки и
ограничения). Инструменты не решают эскиз, а ставят точки в точные положения, поэтому
решённый эскиз остаётся решённым; добавленные ограничения сохраняют результат при следующих
изменениях размеров.

| Инструмент | Алгоритм | Ограничения |
|---|---|---|
| `trimEntity(id, pick)` | пересечения носителя (отрезок — прямая, дуга/окружность — окружность) со всеми живыми сущностями (`Geom2dAPI_InterCurveCurve`), параметр выбранной точки; удаляется кусок между ближайшими пересечениями; середина — разбиение на два элемента; окружность → дуга (нужно ≥ 2 пересечения) | точка на режущей сущности у новых концов; у разрезанного отрезка — оба куска на одной прямой, у дуги — общий центр и равные радиусы; размеры окружности переносятся на дугу |
| `extendEntity(id, pick)` | ближайшее к выбранному концу пересечение за концом (у дуги — в пределах полной окружности) | точка на граничной сущности |
| `offsetChain(ids, d)` | цепочка отрезков и дуг (направление — от первой ко второй); отрезок сдвигается на d влево, радиус дуги ± d по направлению обхода; углы — пересечение смещённых носителей, ближайшее к исходному углу; касательные стыки дают общую точку | отрезок: параллельность + расстояние точка–прямая; дуга: тот же центр + расстояние точка–окружность |
| `mirrorEntities(ids, axis)` | отражение точек; точки на оси переиспользуются; направление дуг меняется | симметрия точек относительно оси; равенство радиусов окружностей |
| `linearPattern(ids, step, n)` | копии со сдвигом k·step | `DistanceX/Y` копии от оригинала = k·step; равенство радиусов окружностей |
| `circularPattern(ids, center, n, step°)` | копии с поворотом k·step вокруг точки | `Rotation` для каждой точки; центр переиспользуется |
| `filletCorner(a, b, r)` | угол двух отрезков с общим концом (или совпадающими концами): t = r / tan(θ/2), центр на биссектрисе на r / sin(θ/2) | касание дуги с обоими отрезками (в общем конце), радиус; вершина угла остаётся точкой на обоих отрезках («виртуальное пересечение»), поэтому размеры до неё сохраняются |
| `chamferCorner(a, b, d1, d2)` | точки на d1 и d2 от угла, новый отрезок | расстояния d1, d2 от вершины; вершина — на обоих отрезках |

Заменённый конец отрезка или дуги, которым больше не пользуется ни одна кривая, удаляется; его
горизонтальность/вертикальность переносится на новый конец (остальные ограничения удаляются
вместе с точкой).

## Пример

```cpp
#include <bendcore/modeling/sketch_tools.hpp>
using namespace bendcore::modeling;

BoundSketch b;
auto& s = b.sketch();
auto p0 = s.add_point(0, 0);  s.fix_point(p0);
auto p1 = s.add_point(41, 1), p2 = s.add_point(39, 21), p3 = s.add_point(1, 19);
auto bottom = b.addLine(p0, p1), right = b.addLine(p1, p2), top = b.addLine(p2, p3), left = b.addLine(p3, p0);
s.constrain_horizontal(p0, p1); s.constrain_vertical(p1, p2);
s.constrain_horizontal(p2, p3); s.constrain_vertical(p3, p0);
auto width = s.constrain_distance(p0, p1, 40);
s.constrain_distance(p1, p2, 20);
b.solve();                                      // "определено", dof = 0
filletCorner(b, right, top, 5);                 // дуга R5, касания, радиус
s.set_constraint_value(width, 60);
auto report = b.solve();                        // скругление следует за размером
auto profile = SketchProfile::build(SketchPlacement::fromPlane(gp_Pln()), b.curves().value());
// площадь 1200 − 25 + 25π/4
```

## Ограничения

- Точка на сплайне и касание сплайна вне концов не поддерживаются (PlaneGCS требует для них
  дополнительный параметр кривой; в эскизе сплайн задаётся полюсами).
- Обрезка и удлинение — для отрезков, дуг и окружностей; режущими могут быть любые кривые.
  Эллипсы и сплайны не обрезаются.
- Зеркало и массивы эллипсов не связывают малую полуось копии с оригиналом (центр и фокус
  связаны); у копии она задаётся отдельно.
- Эквидистанта: цепочка только из отрезков и дуг; если смещённые соседние кривые не
  пересекаются (например, выпуклый угол двух дуг при большом смещении), — ошибка с номерами
  сущностей; скругление стыка не вставляется.
- Инструменты работают на уровне `BoundSketch`; редактирование `SketchData` документа
  (JSON) выполняет вызывающая сторона.
- Определённость по зависимым параметрам — эвристика QR-разложения PlaneGCS: в вырожденных
  положениях (совпадающие точки при диагностике) элемент может быть показан недоопределённым.

## Как тестировать

```bash
cmake --build build-occt --target test_modeling_sketch_solver test_modeling_sketch_tools \
  test_modeling_sketch_profile test_modeling_document_sketch test_sketch2d
ctest --test-dir build-occt -R "sketch" --output-on-failure
```

- `test_modeling_sketch_solver.cpp` — каждое ограничение и размер против аналитики
  (координаты после решения), степени свободы свободных элементов (отрезок 4, окружность 3,
  дуга 5, эллипс 5, дуга эллипса 7, кубический сплайн 8), определённость элементов,
  избыточность и конфликт с номерами, справочные размеры всех видов, неверные операнды.
- `test_modeling_sketch_tools.cpp` — паз из двух отрезков и двух касательных дуг
  (площадь 2RL + πR², после смены радиуса — тоже), сплайн в профиле (площадь против интеграла
  Симпсона = 630), вспомогательная окружность вне профиля; обрезка (конец, разбиение,
  удаление, окружность → дуга), удлинение до окружности, эквидистанта прямоугольника и паза,
  скругление и фаска угла (координаты, площадь, следование за размером), зеркало, массивы.
- `test_modeling_document_sketch.cpp` — паз с касаниями и справочным диаметром в документе
  (объём, имена граней при смене размеров), файлы с дугами в прежнем формате и выживание
  ссылки скругления, эллипс и сплайн в документе, ошибки новых ограничений.
- `tests/test_sketch2d.cpp` — прежний API.
