# Топологическое именование (`bendcore_modeling_document`, naming)

Фаза 1, п. 4 `docs/ROADMAP_GENERAL_CAD.md`; главный риск плана (раздел 6). Заголовок
`include/bendcore/modeling/naming.hpp`, исходники `src/modeling/naming/`, пространство имён
`bendcore::modeling`. Сборка — `cmake/modeling_document.cmake`.

## Назначение

Операция ссылается на грань, ребро или вершину предыдущей формы. После перестроения (другой
размер эскиза, вставка операции выше по дереву) OCCT создаёт новые `TopoDS_Shape`, индексы
`TopExp::MapShapes` меняются. Ссылка поэтому хранит **имя** элемента — устойчивое описание
его происхождения — и **геометрическую сигнатуру** для разрешения неоднозначностей.

## Выбор подхода

| | OCAF `TNaming` | FreeCAD 1.0 (element map, `TopoShape::makeElementShape`) | bendcore |
|---|---|---|---|
| Хранение | Атрибуты `TNaming_NamedShape` в дереве `TDF_Label`, эволюции PRIMITIVE/GENERATED/MODIFY/DELETE | Карта «индекс элемента ↔ имя» у каждой формы, имена строятся из истории `BRepBuilderAPI_MakeShape` и имён соседних элементов, длинные имена сжимаются хэшером строк | Карта у каждой формы (`NamedShape`), имена строятся из `BRepTools_History` и имён соседних граней |
| Разрешение | `TNaming_Selector` / `TNaming_Naming::Solve` — запрос по типу (IDENTITY, UNION, INTERSECTION…) | Поиск по имени, затем по истории; геометрический поиск — опционально | Точное имя → история (псевдонимы, расщепление, удаление) → сигнатура → «сломана» с причиной |
| Встраивание | Требует документа OCAF (`TDocStd_Document`, `TDF_Label`) | Встроено в `Part::TopoShape` | Независимый модуль поверх `TopoDS_Shape` |

Выбран вариант FreeCAD (как и записано в плане): он работает с любым алгоритмом, имеющим
историю, не требует перевода документа на OCAF и даёт читаемые имена. От FreeCAD отличается
тем, что имена изменённых элементов **не** получают метку операции: элемент, изменённый
операцией, вставленной выше по дереву, сохраняет прежнее имя, и ссылки ниже по дереву
разрешаются точно (FreeCAD для этого случая полагается на поиск по истории). Геометрическая
сигнатура, как в плане, — запасной вариант, а не основной механизм.

## Имена

Имя присваивает операция с идентификатором `<fid>` (идентификатор операции документа):

| Происхождение (`NameOrigin`) | Имя | Когда |
|---|---|---|
| `Role` | `<fid>:<роль>` | Элемент создан операцией и назван ею: грани коробки (`Top`, `Bottom`, `Front` = YMin, `Back` = YMax, `Left` = XMin, `Right` = XMax), грани цилиндра (`Top`, `Bottom`, `Side`), грани отверстия (`Wall`, `Tip`, `CounterboreFloor`, …), грани инструмента для массивов (`Tool.F<k>`); элементы профиля эскиза (`<эскиз>:E<id>`, `:R<id>`, `:V<id>_<id>`, `PART_DOCUMENT.md`, «Именование от эскиза») |
| `Unchanged` | имя входного элемента | Тот же подэлемент (`IsSame`) есть в результате |
| `Modified` | имя входного элемента | `History->Modified(x)` даёт ровно один элемент того же типа |
| `Split` | `<имя>;S<i>` | `Modified(x)` даёт несколько элементов; `i` — по геометрическому порядку центров |
| `Generated` | `G[<fid>](<имя источника>)`, при нескольких — `;G<i>` | `History->Generated(x)`, если размерность результата ≥ размерности источника (ребро → грань скругления, ребро профиля → боковая грань) |
| `Derived` | `E(<грани>)`, `V(<грани>)`, `F(<рёбра>)` | Элемент без истории: ребро/вершина — по отсортированным именам смежных граней, грань — по именам своих рёбер |

Правила:

- Кандидаты одного элемента ранжируются: изменённый/неизменный < расщеплённый < порождённый;
  при равном ранге — лексикографически меньшее имя. Остальные кандидаты и унаследованные
  псевдонимы сохраняются в `ElementRecord::aliases`.
- Сечения булевых операций (`Generated` грани → ребро) нарочно не используются: такие рёбра
  получают имя от смежных граней — `E(Body:Top|Pocket:Side+V)`, — которое не зависит от
  размеров.
- Имена `Derived` **не содержат** идентификатор операции, поэтому ребро, укороченное
  скруглением соседнего ребра без записи `Modified` (так ведёт себя `BRepFilletAPI_MakeFillet`),
  получает то же имя, что и до операции.
- Совпадающие имена внутри одной формы различаются суффиксом `;D<i>` в геометрическом
  порядке (центр по x, y, z, затем размер).
- Компоненты длиннее 64 символов внутри составных имён заменяются на `#<FNV-1a 64>` —
  длина имён ограничена при длинных цепочках операций.
- **Журнал удалений**: входной элемент, имя которого не дошло до результата ни прямо, ни как
  псевдоним, ни как часть расщепления, записывается в `NamedShape::deletions()` с
  идентификатором удалившей операции и именами порождённых из него элементов. Журнал
  наследуется по дереву.

Индексы элементов `NamedShape` совпадают с индексами `kernel::TopologyIndex` той же формы
(`TopExp::MapShapes`), поэтому имя доступно по треугольнику вьюпорта.

## Геометрическая сигнатура

`GeometricSignature`: тип геометрии (`Plane`, `Cylinder`, …, `Line`, `Circle`, …, `Point`),
центр (центр масс площади грани / длины ребра / точка вершины), направление (наружная
нормаль плоскости с учётом ориентации грани и «левой» системы координат плоскости; ось
цилиндра, конуса, тора, окружности; направление прямой — оси и прямые в канонической
ориентации), радиус, размер (площадь, длина).

`signatureDistance(a, b, scale)` = ∞, если не совпадают вид элемента, тип геометрии или
направление (косинус < 0,995); иначе
`10·(1 − cos) + |Δцентр|/scale + |Δr|/max(r) + 0,25·|ln(sizeₐ/size_b)|`,
где `scale` — диагональ габарита формы.

## Разрешение ссылки (`resolveReference`)

1. **Точно**: элемент с этим именем. Если имя индексированное (`;D<i>`), а сигнатура соседа с
   тем же базовым именем вдвое ближе, выбирается сосед (метод `Signature`): порядок
   одноимённых элементов мог поменяться.
2. **История**: (а) имя есть среди псевдонимов (элемент слился или переименован) — все такие
   элементы; (б) есть элементы `<имя>;S…` — ссылка указывает на все части расщепления.
3. **Журнал удалений**: если элемент удалён операцией X и из него порождён элемент того же
   вида — ссылка переходит на него (`History`); иначе ссылка **сломана** с причиной
   «edge 'E(Body:Front|Body:Top)' was removed by feature 'Chamfer001' (replaced by
   'G[Chamfer001](E(Body:Front|Body:Top))')». Сигнатура в этом случае не применяется:
   угадывать соседа удалённого ребра нельзя.
4. **Сигнатура**: ближайший элемент, если расстояние ≤ `maxSignatureDistance` (0,35) и он
   однозначен (ближе 0,6 × второго). Иначе — сломана с причиной («no edge … with a matching
   signature (closest distance …)» или «signature is ambiguous (distances … and …)»).

Документ после успешного разрешения обновляет сохранённую сигнатуру ссылки, а при методе,
отличном от точного и с единственным результатом, — и имя (ссылка «следует» за элементом).

## API

```cpp
NamingRequest req{featureId, resultShape, history /* может быть null */, {&inputNamed}, roles};
Result<NamedShape> named = buildNamedShape(req);
Result<TopoReference> ref = makeReference(named.value(), someEdge);
Resolution r = resolveReference(ref.value(), rebuiltNamed);  // r.method, r.indices, r.detail
```

Ошибки: `buildNamedShape` — `InvalidInput` (пустой результат, пустой `featureId`, роль не
грань/ребро/вершина), `OperationFailed` (исключение OCCT); `makeReference` — `InvalidInput`
(элемент не принадлежит форме или не грань/ребро/вершина). `NamedShape::fromRecords`
восстанавливает карту из кэша и проверяет число записей каждого вида.

## Ограничения

- История должна покрывать все входные элементы, которые меняются. Операции, теряющие
  историю (например `ShapeUpgrade_UnifySameDomain` без слияния её истории), дадут элементам
  производные имена; ссылки тогда разрешаются через сигнатуру.
- Порядок частей расщепления и одноимённых элементов — геометрический (по центру). При
  перестановке частей ссылка на одну часть спасается сигнатурой (шаг 1), на все части — не
  зависит от порядка.
- Порождённые грани несут идентификатор операции: при удалении операции и создании новой
  такой же ссылки на её грани разрешаются только по сигнатуре (с предупреждением).
- Сигнатура не различает зеркально-симметричные элементы одинакового размера, если ни имя,
  ни история не помогли: такие ссылки объявляются неоднозначными (сломанными), а не
  угадываются.
- Вершины именуются по смежным граням; у вершины со смежностью к одной грани (шов) имя
  уточняется только индексом.

## Как тестировать

```bash
cmake --build build-occt --target test_modeling_document_naming test_modeling_document_tree \
  test_modeling_document_io test_modeling_document_survival
ctest --test-dir build-occt -R modeling_document --output-on-failure
```

- `test_modeling_document_naming` — карта коробки (6/12/8 уникальных имён, не зависят от
  размеров; ребро y=0, z=H называется `E(B:Front|B:Top)`), история скругления (грань
  `G[F](…)` радиуса 3, укороченное ребро сохраняет имя и длину 17, журнал удалений),
  расстояние сигнатур, разрешение: точно, расщепление (две части суммарной длины 30),
  удалено (причина с именем операции), по сигнатуре (другие имена той же геометрии), без
  сигнатуры — сломана.
- Сценарии документа и измерение доли выживших ссылок — `docs/modeling/PART_DOCUMENT.md`.
