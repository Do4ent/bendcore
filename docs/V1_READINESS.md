# Готовность bendcore к v1.0

Дата: 2026-11-13, ревизия `ccr-d188a25e-rml7z8` после записи журнала «Приняты операции фазы 2 и
доводка интерфейса». Владелец: технический писатель. Основание — `docs/ROADMAP_GENERAL_CAD.md`:
критерий готовности v1.0, минимальный функционал (раздел 2) и критерии «готово» фаз 0–5
(раздел 4).

## 1. Как оценивалось

| Статус | Значение |
|---|---|
| **выполнено** | реализовано на OCCT и проверено автоматическим тестом против независимого эталона; для функций интерфейса — есть в интерфейсе и покрыто сквозным тестом или тестом логики |
| **частично** | реализовано не полностью, только в библиотеке ядра без интерфейса, или проверено только против собственных данных (таблиц, писателя, экспорта bendcore) |
| **нет** | не реализовано |
| **требует человека** | автоматически не проверяется: нужен специалист, официальное издание стандарта, сторонняя программа или внешняя инфраструктура |

Правила строгости:

- Результаты тестов — по записям приёмки в `docs/PROJECT_LOG.md` (последняя: native 125/125,
  нагрузка и fuzz 11/11, WASM node 5/5, Jest 22/22, Playwright 16/16 наборов-сценариев,
  `check_no_stubs.sh` — 0 нарушений). Это локальные прогоны в среде разработки; на GitHub
  Actions они не подтверждены (раздел 4).
- Значение, взятое из таблицы, записанной по памяти, засчитывается только как «частично»:
  тесты сверяют геометрию с той же таблицей и ошибку в ней не поймают
  (`docs/STANDARDS_VERIFICATION.md`).
- Устаревшие отчёты о «завершении» не использовались (`docs/DOCS_CLEANUP.md`).
- «Ядро» — библиотеки C++ (`src/kernel`, `src/modeling`, `src/assembly_v2`, `src/drawing_v2`);
  «интерфейс» — страницы `web/*` поверх WASM-модулей (`README.md`).

## 5. Итоговая оценка

**v1.0 не готова.** По объёму кода фазы 0–4 и большая часть фазы 5 закрыты: ядро на OCCT,
параметрическая деталь с топологическим именованием (388/388 ссылок), решатель сборок, документ
чертежа со спецификацией и экспортом проверены автоматическими тестами против аналитики. Но
критерий готовности v1.0 сформулирован через пользователей и производство, и ни один из его
элементов не проверен.

Блокирует выпуск (по убыванию важности):

1. **Нет проверки людьми** (раздел 4): сверка стандартов, нормоконтроль, производство по
   чертежу, бета, открытие файлов в сторонних CAD. Без сверки стандартов нельзя выпускать
   чертежи и спецификации: размеры крепежа, допуски ISO 286 и графы ГОСТ 2.104/2.106 записаны
   по памяти.
2. **Чертёж — оставшиеся отступления от ЕСКД**: шрифт не тип Б ГОСТ 2.304, позиции деталей
   подсборок не ставятся, резьба не изображается в аксонометрии; правила ГОСТ 2.311, 2.109,
   2.305 реализованы, но их параметры требуют сверки (`STANDARDS_VERIFICATION.md`).
3. **Обмен данными проверен только внутри bendcore**: импорт DXF в интерфейс не выведен;
   STEP/IGES сторонних CAD (импорт и экспорт) не проверялся ни разу.
4. **Корпус STEP**: 13 сгенерированных моделей и 26 STEP эталонных деталей вместо 50–100 файлов
   сторонних CAD (критерий фазы 0); сеть к открытым наборам закрыта прокси.
5. **Интерфейс**: массивы и зеркало тел, удаление тела, траектория по рёбрам модели — без
   сквозных тестов; сообщения ядра только на английском.
6. **CI на GitHub не запускался** в текущем виде; правило «никаких заглушек» в CI фактически не
   действует.
7. Менее критично для бета-версии: шаблоны документов, таблица параметров, выбор вершин и
   фильтры, измерения и сечение во вьюпорте, материалы библиотеки в интерфейсе, плотность в
   файле детали, сообщения ядра на русском, обучающие примеры.

Рекомендуемый порядок: запуск CI на GitHub (п. 6) → сверка стандартов (п. 1) → доработки
чертежа (п. 2) и интерфейса (пп. 3, 5) → сторонний корпус STEP и эталоны (п. 4) → нормоконтроль
10 чертежей → изделие уровня «редуктор» силами внутреннего инженера → бета с КБ.

Документ обновляется при каждой приёмке, которая меняет статус пункта; источник статуса —
запись в `docs/PROJECT_LOG.md` и тест, а не отчёт исполнителя.
