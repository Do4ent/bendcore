# Обмен данными в интерфейсе: импорт STEP/IGES, экспорт STEP/IGES/STL/3MF, массы

Фаза 2.4 `docs/ROADMAP_GENERAL_CAD.md` (обмен данными), п. 3 итоговой оценки
`docs/V1_READINESS.md`. Все файлы пишет и читает ядро в WASM-модулях; интерфейс только выбирает
формат и параметры и скачивает байты.

## Что где

| Действие | Где в интерфейсе | Вызов ядра |
|---|---|---|
| Импорт STEP/IGES как детали (тело без истории) | стартовая страница оболочки «Импорт STEP/IGES…»; «Открыть STEP/IGES…» просмотрщика | `Kernel.importModel(bytes, 'step' \| 'iges')` |
| Импорт STEP/IGES как сборки | то же: файл с несколькими телами или сборкой открывается в редакторе сборки; «Импорт STEP/IGES…» редактора сборки | `AssemblyKernel.importStep` / `importIges` |
| Вставка STEP/IGES деталью в сборку | «Вставить деталь…» сборки (`.json`, `.step`, `.stp`, `.igs`, `.iges`) | `insertPart({format: 'step' \| 'iges'})` |
| Экспорт детали | «Экспорт…» в полосе вкладок оболочки (вкладка детали) | `PartDocumentHandle.exportFile(format, options)` |
| Экспорт сборки | «Экспорт…» редактора сборки и оболочки | `AssemblyDocumentHandle.exportFile(format, options)` |
| Экспорт импортированной модели | «Экспорт…» просмотрщика и оболочки | `KernelShape.exportFile(format, options)` |
| Массовые характеристики детали | «Массовые характеристики» в полосе вкладок оболочки (вкладка детали) | `PartDocumentHandle.massProperties(density)` |
| … импортированной модели | панель «Модель» просмотрщика | `KernelShape.massProperties(density)` |
| … сборки | вкладка «Свойства» правой панели сборки | `AssemblyDocumentHandle.massProperties()` |

Форматы экспорта: STEP AP214/AP242 (единица файла мм, м или дюйм), IGES 5.3 (тела — тип 186,
или обрезанные поверхности — тип 144), STL двоичный/ASCII, 3MF. Для STL и 3MF задаются прогиб
сетки (мм, 0,0001…100) и угловой прогиб (°, 0,5…90); сетка вписана в поверхность, поэтому
объём сетки меньше объёма тела не более чем на площадь × прогиб. Имя файла — имя документа с
расширением формата (`.step`, `.igs`, `.stl`, `.3mf`).

## Редактор детали и оболочка

Редактор детали (`src/ui/modeling/`) в этой работе не менялся (его параллельно меняет инженер
моделирования). Экспорт и массы детали делает оболочка (`src/ui/exchange/partExchange.ts`):
JSON детали, который редактор сообщает после каждого завершённого изменения (тот же текст,
что сохраняется и пишется в черновик), загружается в общий для оболочки модуль детали (свой
воркер, запускается при первом использовании); ядро перестраивает деталь и пишет файл.
Документ держится загруженным, пока JSON не изменится. Следствие: в отдельной странице
`web/part-modeler` экспорта и масс нет; открытая транзакция (панель операции, эскиз) в
экспорт не попадает — экспортируется последнее завершённое состояние.

`EditorHostProps.exportRequest` — счётчик «Экспорт…» оболочки: редактор сборки и просмотрщик
открывают свой диалог, когда число меняется.

## Импорт как деталь или сборка

«Импорт STEP/IGES…» открывает вкладку «Деталь без истории» (`KernelViewerApp` с `importFile`).
Модуль ядра читает файл со структурой XCAF (`readStepAssembly` / `readIgesAssembly`,
`docs/kernel/XCAF_IO.md`) и отдаёт форму (единственная деталь или compound всех деталей в
мировой СК) и `structure`: `assembly` (больше одной детали или корень-сборка), `parts`,
`paths`, `warnings` (сшивка граней IGES и т. п.), `name`, `fileUnitMm`. Если `assembly` —
оболочка заменяет вкладку на вкладку сборки с тем же текстом (`AssemblyApp.importFile`) и
сообщает «N деталей — открыт как сборка». Экспорт импортированной модели пишет её исходную
структуру (имена, цвета, вхождения), а не одну форму.

IGES из обрезанных поверхностей сшивается в тело, корень IGES из нескольких тел становится
сборкой «по детали на тело» (`docs/kernel/XCAF_IO.md`, «IGES»); предупреждения импорта
показываются строкой под панелью инструментов просмотрщика.

## Массовые характеристики

`MassSection` (`src/ui/exchange/MassSection.tsx`): масса (кг), центр масс (мм), диагональ
тензора инерции в центре масс Ixx, Iyy, Izz и произведения Ixy, Ixz, Iyz (кг·мм², знак — как в
ядре: Ixy = −∫xy dm), главные моменты. Считает модуль анализа ядра
(`computeMassProperties`, `docs/kernel/ANALYSIS.md`, раздел 2). Деталь и импортированная модель
— одна плотность (поле раздела, по умолчанию 7850 кг/м³); сборка — плотности деталей из их
свойств (вкладка «Свойства»), суммирование по Штейнеру; детали без плотности перечисляются и в
массу не входят, объём считается по всем.

## WASM-API

```js
const { shape, structure } = kernel.importModel(bytes, 'iges');
const stl = shape.exportFile('stl', { stlFormat: 'binary', linearDeflection: 0.05 });   // Uint8Array
const m = shape.massProperties(7850);           // { mass, volume, area, centerOfMass, inertiaAtCenter, principalMoments, principalAxes }
doc.exportFile('step', { schema: 'AP242', name: 'Bracket' });   // деталь
asm.exportFile('3mf', { linearDeflection: 0.02 });              // сборка: объект на вхождение, цвета
asm.massProperties();                                           // { volume, area, parts, partsWithoutDensity, mass }
assembly.importIges(text);
kernel.exchangeInfo().zipMethod;                                // 'stored' в WASM
```

Общий код трёх модулей — `src/wasm/exchange_common.hpp` (разбор параметров, запись по
формату, перевод масс в JS). Ошибочные параметры — `InvalidInput`; ошибки ядра — его коды
(`ParseError` для не-IGES, `Unsupported` и т. д.). Длинные вызовы (`importModel`, `importIges`,
`exportFile`) показываются индикатором оболочки (`LONG_OPERATIONS`).

3MF в WASM пишется ZIP без сжатия: zlib для Emscripten недоступен без сети
(`docs/kernel/ANALYSIS.md`, «ZIP и zlib»); диалог экспорта сообщает об этом.

## Как тестировать

```bash
# сборка — docs/ui/APP_SHELL.md, «Как тестировать»
ctest --test-dir build-wasm-all -R wasm_exchange --output-on-failure
npx jest src/ui/exchange
npx playwright test -c web/app/playwright.config.ts exchange
```

- `tests/wasm/exchange.test.mjs` (node): STEP AP214/AP242 детали → импорт (объём 10⁻⁹, 6
  граней, имя PRODUCT, ключ схемы); IGES в обоих режимах (цилиндр: объём 10⁻⁵, 1 тело, 3 грани,
  предупреждение о сшивке); единицы м и дюйм; STL двоичный и ASCII читаются читателем теста —
  сетка замкнута и ориентирована, 0 ≤ V − V_сетки ≤ S·δ, более мелкий прогиб ближе к V; 3MF —
  ZIP разбирается тестом, CRC каждой записи сверяется `zlib.crc32` node, метод записей совпадает
  с `exchangeInfo`, три XML разбираются строгим разборщиком теста, единица `millimeter`, сетка
  замкнута, объём в границах прогиба, плюс Python `zipfile.testzip()` и `xml.dom.minidom`; порча
  байта ловится CRC; массы бруса против формул (m, центр, Ixx, Iyy, Izz, главный момент);
  корпус IGES (`manifest.json`, раздел `iges`); сборка из IGES — 4 вхождения, 3MF с четырьмя
  объектами и тремя цветами, STEP/IGES туда и обратно, масса и центр масс против формул.
- `src/ui/exchange/__tests__/exchange.test.ts` (Jest): расширения и имена, разбор параметров и
  диапазоны, плотность, тензор, `PartExchange` (один воркер, документ на JSON, порядок).
- `tests/e2e-app/exchange.spec.ts` (Playwright): пользователь строит брусок 60×40×20,
  экспортирует STEP AP242 (скачанный файл читается модулем ядра в node: объём, 6 граней) и
  двоичный STL (12 треугольников, замкнут, объём точный); масса в панели оболочки; импорт
  `plate_120x80x10_hole_d20_faces.igs` — деталь без истории, объём по формуле, сшивка, масса;
  импорт `assembly_bracket_pins.igs` — вкладка сборки с 4 вхождениями, экспорт 3MF (CRC записей,
  4 объекта).

## Ограничения

- Экспорт и массы детали только в оболочке (см. выше); транзакция редактора не экспортируется.
- Импорт DXF в интерфейс не выведен; STL как опорная сетка не импортируется.
- IGES без структуры изделия: сборка читается списком деталей; слои не пишутся.
- 3MF в WASM без сжатия; STL одной сетью для всей сборки (без цветов).
- Файлы сторонних CAD не проверялись: корпус — синтетический (`tests/corpus/README.md`).
