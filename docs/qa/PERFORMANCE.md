Каждый замер — `timed(тест, шаг, порог, …)` из `stress_util.hpp`: печатает строку
`[stress] <UTC> <тест> <шаг> <с> (limit …) peakRSS …` и дописывает строку JSON с меткой времени в
`BENDCORE_STRESS_REPORT` (ctest: `build-occt/stress-report.jsonl`):

```json
{"time":"2026-11-11T16:26:06Z","test":"part_300","step":"rebuild_after_sketch_edit","seconds":63.705,"limit_seconds":180.0,"peak_rss_mib":188}
```

Порог умножается на `BENDCORE_STRESS_TIME_SCALE` (CI: 1,5). Пороги заданы с запасом 2–3× к
базовой линии (раздел 2), чтобы ловить деградацию в разы, а не шум машины.

## 3. Наблюдения (профилирование — следующий шаг)

1. **Деталь из 300 операций: ~0,4 с на вырез.** Перестроение 149 вырезов растёт с числом
   отверстий (каждый вырез — булева операция над телом с уже сделанными отверстиями плюс
   построение карты элементов топологического именования по всем граням результата). Холостое
   перестроение и загрузка с кэшем — секунды, т. е. стоимость именно в пересчёте. Кандидаты
   для профилирования: `BRepAlgoAPI_Cut` на растущем теле и сопоставление граней в
   `src/modeling/naming/` (квадратичность по числу граней).
2. **Пересечения сборки: ~74 с на 299 пар.** Отбор по габаритам работает (299 кандидатов из
   44 850), но каждая пара «штифт — плита с 299 отверстиями» — `booleanOp(Common)` и
   `BRepExtrema_DistShapeShape` по всей плите. Для крупных деталей нужна локализация (обрезка
   плиты габаритом второго тела) или параллельный расчёт пар.
3. **Крупный STEP:** импорт ~22 с на 65 МиБ (≈ 3 МиБ/с), пик памяти ≈ 10 × размер файла. Файл
   100 МБ (цель плана фазы 5) потребует ≈ 1 ГиБ — для WASM (2–4 ГиБ) это предел, что
   подтверждает риск «Память WASM» плана.
4. **HLR 1000 граней:** точный вид сверху — доли секунды; изометрия с выбором алгоритма — ~7 с.

## 4. Как запускать

```bash
cmake --build build-occt --target test_stress_part test_stress_assembly test_stress_step \
  test_stress_hlr generate_corpus
ctest --test-dir build-occt -L stress --output-on-failure        # последовательно
cat build-occt/stress-report.jsonl
# крупный STEP другого размера:
cmake build-occt -DBENDCORE_STRESS_STEP_MB=110 && ctest --test-dir build-occt -R stress_step
```

Тесты входят и в полный `ctest`; в CI они идут отдельным последовательным шагом вместе с
`performance` и `offset_performance` (`docs/qa/QA.md`, раздел 4).
