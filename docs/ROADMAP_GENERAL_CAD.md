# bendcore: план развития до полноценной CAD-системы

Дата: 2026-11-06. Статус: проект плана, требует утверждения.

Цель: минимально необходимый, но полноценный функционал машиностроительной CAD —
параметрическая деталь, сборка, ассоциативный чертёж — на уровне общего знаменателя
SolidWorks, Inventor, Siemens NX, CATIA, Creo и КОМПАС-3D, с оформлением по ЕСКД и ISO.

Критерий готовности v1.0: инженер проектирует в bendcore изделие уровня
«редуктор / гидроцилиндр» (15–30 деталей, крепёж из библиотеки), получает сборку,
рабочие и сборочный чертежи со спецификацией по ГОСТ 2.106, и производство принимает
эти чертежи без перерисовки в другой системе.

| Виды | Стандартные (ГОСТ 2.305), проекционные, дополнительные, изометрия; разрез полный/местный, сечение, выносной элемент; видимые/невидимые линии (HLR); масштабы по ГОСТ 2.302 |

| Аннотации | Шероховатость (ГОСТ 2.309), допуски формы и расположения (ГОСТ 2.308 / ISO 1101), базы, технические требования, выноски, позиции |
| Спецификация | По ГОСТ 2.106 из состава сборки, позиции синхронизированы с видом |
| Экспорт | PDF (векторный, в масштабе), DXF, SVG; печать |

### 2.4 Обмен данными и платформа

- Импорт: STEP AP203/214/242, IGES, DXF, STL (как mesh для справки).
- Экспорт: STEP AP214/242 (сборка, имена, цвета), STL/3MF, DXF, PDF.
- Собственный формат с историей построения, версионированием и миграцией.
- Отмена/повтор на уровне транзакций, автосохранение и восстановление после сбоя.
- Вьюпорт: навигация, выбор граней/рёбер/вершин, фильтры выбора, сечение модели, измерения.

### 2.5 Сознательно НЕ входит в v1.0

DWG (нужна коммерческая библиотека ODA; LibreDWG под GPL несовместим с MIT),
Parasolid/ACIS, конфигурации и исполнения, листовой металл, поверхностное моделирование
класса A, сварные конструкции, проектирование в контексте сборки, кинематический анализ,
FEA/CFD-интеграция в интерфейс, CAM, PDM/PLM, совместная работа.

## 3. Архитектурные решения

| Вопрос | Решение | Обоснование |
|---|---|---|
| Геометрическое ядро | OCCT 8.0.1 с явным набором модулей + слой `geometry_healing` в bendcore | Своё ядро — годы работы; OCCT уже собран и протестирован в проекте |
| Набор модулей OCCT | TKernel, TKMath, TKG2d, TKG3d, TKGeomBase, TKBRep, TKGeomAlgo, TKTopAlgo, TKPrim, TKBO, TKBool, TKFeat, TKFillet, TKOffset, TKShHealing, TKMesh, TKHLR, TKXSBase, TKDE, TKDESTEP, TKDEIGES, TKDESTL, TKXCAF, TKLCAF, TKCAF, TKCDF (+ зависимости XCAF проверить для 8.0.1) | HLR нужен для чертежей, TKFeat — для отверстий/карманов, XCAF — для структуры сборки в STEP |
| Эскиз | PlaneGCS (уже есть) | Рабочий, LGPL |
| Топологическое именование | Карта элементов на основе истории OCCT (`Generated` / `Modified` / `IsDeleted`) + геометрическая сигнатура как запасной вариант | Подход FreeCAD 1.0; `TNaming` из OCAF сложнее встроить в существующий документ |
| Решатель сборок | Собственный: 6 степеней свободы на компонент, Левенберг — Марквардт на Eigen, разбиение на независимые подсистемы, ранговый анализ якобиана для диагностики | SolveSpace (GPLv3) несовместим с MIT; задача хорошо изучена |
| HLR для чертежей | `HLRBRep_PolyAlgo` для черновика, `HLRBRep_Algo` для точного вида, в фоновом потоке | Встроено в OCCT |
| PDF | libharu (zlib) или собственный писатель векторного PDF | Пермиссивная лицензия |
| DXF | Собственный писатель (R12/R2000) | Формат открыт, объём небольшой |
| Сетка для FEA (после v1.0) | Netgen (LGPL) + разреженный решатель Eigen | Gmsh под GPL |
| Интерфейс | Один интерфейс: существующий React + three.js; ядро в браузере через WASM, на десктопе — нативное ядро в оболочке Tauri/Electron | Qt-кода нет; два интерфейса команда не потянет |
| Передача геометрии во вьюпорт | Тесселяция `BRepMesh` → буферы вершин и индексов + таблица «диапазон треугольников → ID грани» для выбора | Нужна для выбора граней и рёбер |

Обновление three.js 0.128 → актуальная версия — отдельная задача фазы 1.

## 4. Фазы реализации

Оценки даны для команды из 5–6 инженеров: архитектор/геометрия, 2 разработчика ядра,
разработчик чертежей, фронтенд, QA. Срок по каждой фазе — календарный.

### Фаза 0. Фундамент ядра — 3 недели

1. Пересобрать OCCT с явным набором модулей (раздел 3) для native и WASM; заменить
   `file(GLOB …libTK*.a)` (CMakeLists.txt:150) явным списком; замерить размер `.wasm`.
2. Модуль `geometry_healing`: ShapeFix, UnifySameDomain, перевод NURBS в аналитику,
   булевы операции с повышением допуска и проверкой `BRepCheck_Analyzer`.
3. Удалить заглушки: `src/geometry/brep_builder.cpp`, `feature_operations.cpp`,
   placeholder-экспорт в `drawing_export.cpp`, их тесты из `BENDCORE_UNVERIFIED_TARGETS`.
4. Абстракция `Shape` в bendcore поверх `TopoDS_Shape`, сериализация BRep.
5. API тесселяции с привязкой треугольников к граням; WASM-биндинг.
6. Корпус тестовых моделей: 50–100 STEP-файлов разных CAD, регрессия импорта в CI.

Готово, когда: OCCT собирается в CI в обеих конфигурациях; импорт корпуса STEP без
падений; тесселированная модель отображается во вьюпорте с выбором граней.

### Фаза 1. Деталь, базовый уровень — 10 недель

1. Модель документа детали: дерево операций, каждая операция — вход (эскиз, ссылки,
   параметры) → `Shape`; перестроение по графу зависимостей (существующий `rebuild_engine`
   начинает строить геометрию).
2. Эскиз на плоскости и на плоской грани; проекция рёбер модели в эскиз.
3. Операции: выдавливание/вырез (все условия окончания из 2.1), вращение, отверстие
   (простое, зенковка, цековка), скругление, фаска, линейный/круговой массив, зеркало,
   вспомогательные плоскости и оси.
4. Топологическое именование v1: карта элементов, переживающая изменение размеров
   эскиза и вставку операции выше по дереву.
5. Переменные и выражения, связанные с размерами.
6. Сохранение/загрузка собственного формата с историей, миграция версий.
7. Интерфейс: дерево построения, панели операций (переиспользовать React-панели из
   `src/features/modeling`), выбор, предпросмотр.

Готово, когда: 10 эталонных деталей (кронштейн, вал со шпоночным пазом, фланец,
крышка, корпус) строятся с нуля; изменение любого размера эскиза перестраивает модель
без потери скруглений и отверстий в ≥ 95 % сценариев теста именования; файл
сохраняется и открывается без расхождений.

### Фаза 2. Деталь, полный уровень v1.0 — 8 недель

1. Кинематика, по сечениям, оболочка, уклон, ребро жёсткости, тонкостенные операции.
2. Резьбовые отверстия по ISO/ГОСТ, условное изображение резьбы.
3. Многотельная деталь, булевы операции между телами.
4. Материалы, масса и инерционные характеристики (`BRepGProp`).
5. Подавление, откат, перенос операций; диагностика ошибок перестроения в дереве.
6. Экспорт STEP AP214/242, STL/3MF; лечение геометрии при импорте в интерфейсе.
7. Инструменты: измерение, сечение модели плоскостью.

Готово, когда: эталонный набор расширен до 25 деталей, включая литой корпус с уклонами
и оболочкой; масса совпадает с эталонной CAD в пределах 0,1 %; экспорт STEP открывается
в двух сторонних системах без ошибок.

### Фаза 3. Сборка — 10 недель

1. Документ сборки: экземпляры компонентов со ссылками на документы деталей, подсборки,
   фиксация, замена.
2. Решатель сопряжений (раздел 3), набор сопряжений из 2.2, индикация степеней свободы,
   диагностика переопределённых и противоречивых сопряжений.
3. Перетаскивание с учётом сопряжений, проверка пересечений (`BRepAlgoAPI_Common` по
   парам с предварительным отбором по габаритам).
4. Массив компонентов, в том числе по массиву детали.
5. Библиотека крепежа ГОСТ/ISO: параметрические генераторы (болт ГОСТ 7798, винт ГОСТ
   17473, гайка ГОСТ 5915, шайба ГОСТ 11371, ISO 4014/4032/7089 и т. п.).
6. Состав изделия (BOM), разнесённый вид.
7. Импорт/экспорт сборок STEP с сохранением структуры, имён, цветов.

Готово, когда: эталонная сборка из 30 компонентов и 80 сопряжений решается быстрее
0,5 с; изменение размера детали корректно обновляет сборку; импортированная из STEP
сборка сохраняет структуру.

### Фаза 4. Чертежи — 12 недель

1. Модель чертежа: листы, форматы, шаблоны основной надписи ЕСКД и ISO.
2. Виды: стандартные, проекционные, дополнительные, изометрия; HLR в фоне с кэшем;
   ассоциативное обновление при изменении модели.
3. Разрезы, сечения, местные разрезы, выносные элементы; штриховка по материалу.
4. Осевые линии, центровые метки, обозначения видов и разрезов.
5. Размеры с привязкой к рёбрам вида (через топологическое именование), допуски и
   посадки, автоматическая простановка размеров эскиза (опционально).
6. Аннотации: шероховатость, допуски формы и расположения, базы, технические требования,
   выноски, позиции.
7. Спецификация ГОСТ 2.106 и таблица BOM ISO, синхронизация позиций.
8. Экспорт PDF (векторный, в масштабе), DXF, SVG; печать.

Готово, когда: по каждой эталонной детали и сборке выпускается комплект чертежей;
нормоконтролёр проверяет 10 чертежей на соответствие ЕСКД без замечаний по оформлению;
PDF и DXF корректно открываются в сторонних программах в масштабе 1:1.

### Фаза 5. Стабилизация и бета — 8 недель

1. Производительность: сборка из 300 компонентов, деталь из 300 операций, большой
   STEP (≥ 100 МБ); профилирование, многопоточность там, где позволяет OCCT и WASM
   (pthreads требуют заголовков COOP/COEP).
2. Надёжность: автосохранение, восстановление после сбоя, fuzz-тесты загрузки файлов.
3. UX: горячие клавиши, контекстные меню, шаблоны документов, локализация RU/EN.
4. Документация пользователя и обучающие примеры.
5. Закрытая бета с 3–5 конструкторскими бюро; сквозной сценарий «изделие → чертежи →
   производство».

Готово (= v1.0): критерий готовности из начала документа выполнен у бета-пользователей;
нет известных ошибок с потерей данных.

## 6. Главные риски

| Риск | Влияние | Меры |
|---|---|---|
| Топологическое именование | Модели «ломаются» при редактировании; главный источник недовольства в FreeCAD | Заложено в фазу 1, отдельный набор регрессионных тестов, геометрическая сигнатура как запасной вариант |
| Надёжность скруглений и оболочек OCCT | Отказ операций на сложной геометрии | Понятная диагностика в дереве, повтор с изменённым допуском, порядок операций как в эталонных системах |
| Производительность HLR | Медленное обновление чертежей | Фоновый расчёт, PolyAlgo для черновика, кэш по версии модели |
| Память WASM | OCCT в браузере ограничен 2–4 ГБ | Нативная версия для крупных сборок, облегчённые представления компонентов |
| Решатель сборок | Нестабильность на переопределённых системах | Разбиение на подсистемы, ранговый анализ, тесты на эталонных механизмах |
| Расфокус | Работа над отчётами и побочными направлениями вместо ядра | Критерии «готово» по каждой фазе проверяются только тестами и эталонными моделями |

## 7. Ближайшие шаги

1. Утвердить план и состав команды.
2. Фаза 0, п. 1: пересборка OCCT с явным списком модулей, замер размера WASM.
3. Фаза 0, п. 3: удаление заглушек геометрии и экспорта чертежей.
4. Собрать корпус эталонных STEP-моделей и эталонных деталей для фаз 1–2.
