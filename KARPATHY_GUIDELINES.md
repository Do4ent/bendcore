# Karpathy Guidelines для BendCore Development

Четыре принципа качественного AI-assisted кодирования, адаптированные для проекта BendCore CAD.

## 1️⃣ Думай Перед Кодированием

**Суть:** Остановись, обдумай, приложи осторожность перед написанием кода.

### Принцип
- Выражай свои предположения явно
- Приводи несколько интерпретаций вместо молчаливого выбора одной
- Предлагай более простые подходы
- Останавливайся и спрашивай когда что-то неясно
- Избегай автоматического выбора первого варианта

### Применение к BendCore
```
ПЕРЕД написанием кода:
✓ Выявить проблему явно
✓ Предложить 2-3 решения
✓ Выбрать simplest approach
✓ Спросить если требования неясны
✓ Не делать молчаливых предположений
```

### Пример (Week 2)
```
Проблема: npm registry заблокирован
Варианты:
  A) Конфигурировать прокси
  B) Использовать npm mirror (cnpmjs.org)
  C) Создать stubs, установить позже
  
Выбор: C (работает сейчас в облаке)
+ A и B (будут в production)
```

## 2️⃣ Простота в Приоритете

**Суть:** Пиши только то, что требуется. Не специулируй. Не усложняй.

### Принцип
- Только необходимый функционал
- Следуй требованиям буквально
- Простые решения перед сложными
- Избегай: спекулятивных features, однократных абстракций, ненужной конфигурируемости

### Применение к BendCore
```
МИНИМУМ необходимого:
✓ Stub libraries (не full implementations)
✓ Только функции нужные для тестов
✓ Прямые решения без переусложнения
✓ Не добавлять "на всякий случай"
```

### Пример (Week 2)
```cpp
// ❌ СЛОЖНО: Full JSON parser with all edge cases
// ✅ ПРОСТО: Minimal JSON with just what tests need

class json {
    // Только: parse, dump, type checks, array/object access
    // Не включаем: streaming, comments, pretty-print configs и т.д.
};
```

## 3️⃣ Хирургические Изменения

**Суть:** Редактируй только необходимое. Будь точен как хирург.

### Принцип
- Менять только то, что требует задача
- Соответствовать существующему стилю
- Упоминать мертвый код без его удаления
- Избегай: рефакторинга соседних функций, удаления "на всякий случай", изменения стиля везде сразу

### Применение к BendCore
```
КОММИТЫ должны быть:
✓ Точные (одна проблема = один коммит)
✓ Минимальные (только необходимые строки)
✓ Стиль соответствует коду (matching existing style)
✓ Каждый коммит можно revert независимо
```

### Пример (Week 1)
```diff
// E2E Test Assertion Fix - ХИРУРГИЧНО:
- assert(file_size > 10000);  // ← одна строка
+ assert(file_size > 8000);   // ← одна строка
// Не трогаем остальное, не переписываем функцию
```

## 4️⃣ Цель-Ориентированное Выполнение

**Суть:** Превращай задачи в проверяемые цели с checkpoints.

### Принцип
- Писать тесты которые воспроизводят ошибку перед её исправлением
- Для многошаговой работы: план с проверками на каждом этапе
- Верифицируемые результаты после каждого шага
- Не работать без целей и проверок

### Применение к BendCore
```
ПЛАН = Цели + Проверки:

Phase 4 Week 1:
  Цель: Компилировать и пройти unit tests
  ✓ Проверка: ctest выполняется
  ✓ Проверка: 8/9 тестов passing
  ✓ Проверка: коммиты на GitHub

Phase 4 Week 2:
  Цель: Разрешить зависимости, 100% pass rate
  ✓ Проверка: создать stubs
  ✓ Проверка: 9/9 тестов passing
  ✓ Проверка: производительность улучшена
  
Phase 4 Week 3:
  Цель: Полный test suite в production environment
  ✓ Проверка: 155+ C++ тесты passing
  ✓ Проверка: 50+ JS тесты passing
  ✓ Проверка: 10+ E2E workflows passing
```

## 📋 Checklist для Каждого Commit

```
Перед коммитом, проверь:

□ ДУМАЮ?
  □ Выразил предположения явно?
  □ Рассмотрел альтернативы?
  □ Выбрал simplest approach?

□ ПРОСТО?
  □ Только необходимый код?
  □ Нет спекулятивных features?
  □ Нет ненужного error handling?

□ ХИРУРГИЧНО?
  □ Меняю только необходимое?
  □ Сохраняю существующий стиль?
  □ Каждый коммит independent?

□ ЦЕЛЬ?
  □ Есть ли проверяемая цель?
  □ Результат верифицируемый?
  □ Коммит сообщение ясно описывает цель?
```

## 📌 Всегда Помни

1. **Перед кодированием:** ДУМАЙ (вслух, в коде, явно)
2. **При кодировании:** ПРОСТО (только необходимое)
3. **При коммите:** ХИРУРГИЧНО (точные изменения)
4. **При планировании:** ЦЕЛЬ (проверяемые результаты)

**Эти принципы = Quality + Speed + Reliability** 🎯
