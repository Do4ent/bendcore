# Recon: трубные модули 6 CAD → что внедрить в BendCore

Дата: 2026-10-23. Методика: replica-recon (только публичные источники, без кода и приватных API).
Цель: не скопировать чужую программу, а взять проверенные решения по функциям и интерфейсу
для гнутой круглой трубы (деталь и труба в сборке), с учётом уже принятых решений BendCore.

Метки достоверности: **[источник]** — прочитано в справке по ссылке; **[знание]** — общеизвестное
поведение программы, справку прочитать не удалось (SOLIDWORKS Help не отдаётся без JS) — сверить
перед реализацией.

## 3. Как это устроено у шести систем (сравнение)

### 3.1 Путь трубы

| | Inventor | SOLIDWORKS | NX | Creo | Solid Edge | CATIA |
|---|---|---|---|---|---|---|
| Ручной путь | 3D-эскиз маршрута, инструмент «3D Orthogonal Route» с осями и ручками поворота **[источник]** | 3D-эскиз маршрута **[знание]** | Путь с ручками и наклоном, авто-ограничения **[источник]** | Маршрут по точкам **[знание]** | XpresRoute: путь из линий и дуг **[знание]** | Run между коннекторами / в пространстве / из файла **[источник]** |
| Авто-путь | Auto region между двумя точками по правилам стиля **[источник]** | Auto Route **[знание]** | — | — | — | — |
| Путь из существующей геометрии | Derived route из base sketch детали **[источник]** | — | «Существующие кривые» **[источник]** | — | — | Route From a Spline, Offset Route **[источник]** |
| Где гиб | В вершине, радиус по стилю, можно переопределить на гиб **[источник]** | В вершине **[знание]** | В вершине или сплайн **[источник]** | В вершине **[знание]** | В вершине, радиус из свойств трубы **[источник]** | Turn radius в узле **[источник]** |

Вывод для BendCore: модель «острые вершины + радиус из профиля» совпадает с общим подходом
всех шести. Расхождение — переопределение радиуса на отдельный гиб (Inventor). В BendCore
это решено иначе и правильно для цеха: радиус меняется только сменой трубогиба. Не копировать.

### 3.2 Назначение трубы и правила

| | Где задаются | Что содержит |
|---|---|---|
| Inventor | Стиль (Tube & Pipe Styles) | OD/ID, материал из библиотеки, радиус по умолчанию, min/max длина сегмента и шаг округления **[источник]** |
| Solid Edge | Tube Properties | OD, стенка, радиус, Minimum Flat Length **[источник]** |
| Creo | Спецификация (spec-driven) + bend table | Таблицы развёрнутой длины R×OD, интерполяция **[источник]** |
| NX | Спецификации XML + design rules | Мин. радиус, мин. прямой участок, свои правила, интерактивно/пакетно **[источник]** |
| CATIA | Line ID + design rules | Выбор спецификации через Line ID; часть правил задаёт администратор, их нельзя обойти **[источник]** |

Вывод: у BendCore эта роль разделена на «назначение трубы» (номенклатура/материал) и «профиль
трубогиба» (R, S_min, N, B_min/B_max) — это ближе всего к Creo+NX и сильнее, чем стиль Inventor,
потому что ограничения привязаны к станку, а не к трубе. Взять у CATIA идею «правил
предприятия, которые пользователь не может ослабить» — она ложится на уже принятый
«Профиль предприятия».

### 3.3 Проверка технологичности

| | Как |
|---|---|
| Inventor | Проверка остатка длины сегмента при добавлении гиба **[источник]** |
| NX | Набор правил, запускаемых по ходу работы или пакетом; свои правила **[источник]** |
| CATIA | Validate Run Turns; Validation Report **[источник]** |
| Creo | Ограничение 1,5° на сегмент для отчётов **[источник]** |

Вывод: у BendCore уже есть единая таблица классов нарушений (ошибка/предупреждение/информация).
Не хватает режима NX: «проверить все трубы сборки пакетом» с отчётом и переходом к нарушению.

### 3.4 Выходные данные

| | Форматы и состав |
|---|---|
| Inventor | Bending Machine data, ASCII: XYZ (точки + R) и YBC/LRA (длина, поворот, угол + R), плюс ∅, стенка, материал **[источник]** |
| Creo | Bend Location (№, XYZ в выбранной СК, угол, R) и Bend Machine (№, точка, угол, R, twist), от выбранного конца **[источник]** |
| Solid Edge | Bend Table ASCII для одной или всех труб **[источник]** |
| NX | Отчёты XYZ и YBC, BOM, длины реза **[источник]** |
| SOLIDWORKS | Данные гибки для ЧПУ, BOM с длинами реза, Pipe Drawing **[источник]** |

Вывод: стандарт отрасли — пара XYZ + YBC(LRA) с выбором «от какого конца» и «в какой СК».
У BendCore есть структура карты гибки (`BendCard` в include/bendcore/reporting.hpp): радиусы,
углы, прямые участки, длина заготовки. В ней **нет угла поворота плоскости гиба**, поэтому
полноценный LRA из неё не собрать; файлов экспорта LRA/YBC и XYZ в коде нет (поиск по
src/include — 0 совпадений).

### 3.5 Чертёж

SOLIDWORKS Pipe Drawing: изометрия, размеры по оси, BOM с длинами реза, авто-позиции **[источник]**.
Остальные — через отчёты/таблицы на листе (Creo bend tables, NX run/spool numbering) **[источник]**.

Вывод: у BendCore спецификация чертежа (развёртка, лист развёрток, выпуск, ассоциативность)
уже глубже любой из шести. В коде есть только данные (UnfoldingSpec, unfold_drawing),
среды чертежа (лист, виды, размеры, выпуск) нет. Это самый крупный пробел.

### 3.6 Сборка и повторное использование

| | Как |
|---|---|
| Inventor | Primary occurrence редактируется, secondary — копии без правки, обновляются от primary **[источник]** |
| CATIA | Break Run, Transfer, Spool, Copy/Paste систем **[источник]** |
| NX | Fabrications, нумерация runs/spools для документации **[источник]** |

Вывод: идея Inventor primary/secondary — это то же, что «сигнатура одинаковых труб» BendCore,
но с явной ролью «главный экземпляр». Стоит взять в UI: значок главного экземпляра и команда
«Сделать главным».

## 4. Экраны (S) — что нужно BendCore, с образцом

| ID | Экран | Как попасть | Назначение | Образец | Есть в BendCore |
|---|---|---|---|---|---|
| S01 | Главное окно: лента, дерево, 3D, свойства, строка состояния | запуск | оболочка | SOLIDWORKS | да (Phase 29–34) |
| S02 | Новая труба (назначение + трубогиб) | Труба → Новая | старт трубы | стиль Inventor / Line ID CATIA | да (NewTubeDialog) |
| S03 | Среда пути трубы (edit-in-place, «Завершить») | двойной клик по трубе | 3D-эскиз | Route env Inventor | частично (PathSketch3D) |
| S04 | Ортогональный инструмент направления в точке | в S03 | задать направление сегмента | 3D Orthogonal Route Inventor | нет |
| S05 | Таблица гибов (режимы «Эскиз»/«Таблица») | панель трубы | видеть/править L-S-B-A | Creo Bend Location | частично |
| S06 | Параметры трубогибов | Сервис → Трубогибы | профили | Tube Properties SE / bend table Creo | да (ProfileDialog) |

| S08 | Экспорт данных гибки (XYZ/LRA, конец, СК) | Вывод → Данные гибки | файл для станка | Inventor/Creo/SE | нет (есть только BendCard без угла поворота) |
| S09 | Мастер чертежа трубы | Чертёж → Новый | виды, развёртка | SOLIDWORKS Pipe Drawing | нет |
| S10 | Лист развёрток | Чертёж → Лист развёрток | все трубы на листе | (нет аналога) | нет |
| S11 | Выпуск чертежа | Чертёж → Выпустить | блокировки, роль | (нет аналога) | нет |
| S12 | Импорт (фильтр, распознавание, округление) | Файл → Импорт | DWF/DWFx/STEP | (у шести нет распознавания на таком уровне) | да (ImportDialog) |
| S13 | Порты: создание/правка | Сборка → Порт | точки подключения | коннекторы CATIA, точки Inventor | частично (ports.cpp) |

Состояния, которые нужно предусмотреть у каждого экрана: пусто, загрузка, норма,
нарушение-ошибка, нарушение-предупреждение, только чтение (выпущено / замороженная труба).

## 5. Сценарии (F)

```
F01 Труба между двумя портами в сборке
    S02 → S03 (+S04) → S05 → S07
    edge: порт с вылетом < N; прямой участок < S_min; гиб вне B_min..B_max; коллизия с окружением
F02 Исправить нарушение
    S07 → двойной клик по строке → S03 с подсветкой вершины → правка → повторная проверка
F03 Выдать данные в цех
    S05 → S08 (выбор конца А/Б, формат XYZ или LRA, компенсация пружинения) → файл
    edge: технологическая ошибка блокирует вывод
F04 Чертёж трубы
    S09 → виды + развёртка → размеры S → S11
F05 Импорт чужой сборки
    S12 → фильтр окрестности → распознавание → трубы «Заморожены» + автопорты → S07
F06 Одинаковые трубы в сборке
    копирование → S14 (главный экземпляр) → правка главного → обновление копий
F07 Пакетная проверка всей сборки перед выпуском
    S07 → отчёт → S11
```

## 6. Компоненты интерфейса, которые стоит взять

| Компонент | Откуда | Зачем в BendCore |
|---|---|---|
| Триада направления с ручками поворота в точке пути | Inventor 3D Orthogonal Route | быстрый ввод ортогональных сегментов без ручных размеров |
| Edit-in-place среда с кнопкой «Завершить» | Inventor route environment | одна понятная граница «правлю путь / вернулся в сборку» |
| Отчёт-таблица, сохраняемая как элемент дерева | Creo «save analysis» | таблица гибов и проверка как живые узлы, обновляются сами |
| Браузер нарушений с переходом к месту | NX design rules / CATIA Validation Report | F02 за два клика |
| Значок «главный экземпляр» | Inventor primary occurrence | понятность повторяющихся труб |
| Переключатель «от конца А / от конца Б» в выводе | Creo Bend Machine | у цеха разные стороны подачи |

## 7. Модель данных (что подтверждает или добавляет разбор)

```
BendReport  tube_id, format (XYZ | LRA), start_end (A | B), csys_id,
            rows[]: n, x,y,z | L, R(rotation), A(angle), radius, twist
            evidence: Creo Bend Machine/Location, Inventor XYZ/YBC   confidence: high
RuleRun     id, scope (tube | assembly), mode (interactive | batch), started_at,
            violations[]: tube_id, vertex_id, class, rule_id, value, limit
            evidence: NX design rules, CATIA Validation Report       confidence: high
TubeInstance tube_id, signature, is_primary, primary_id
            evidence: Inventor primary/secondary occurrence          confidence: high
BendAllowanceTable  profile_id, rows: R, OD, developed_len_90, interp=linear
            evidence: Creo spec-driven bend table                     confidence: high
```

## 8. Что не брать и почему

| Что | Почему |
|---|---|
| Фитинги, отводы, Content Center, ISOGEN/PCF | вне области v1 (только одиночная гнутая круглая труба) |
| Гибкие шланги, FLEX-алгоритм CATIA | вне области (жёсткая труба) |
| Переопределение радиуса на один гиб (Inventor) | противоречит решению BendCore «один R на ∅ на инструмент» |
| Сплайновые пути (NX, CATIA) | не гнутся на трубогибе, BendCore строит только из острых вершин |
| Названия, значки, тексты справки, форматы файлов-шаблонов чужих программ | собственность производителей; брать только функцию |
| Авто-трассировка между портами | в результатах поиска есть патенты Dassault на маршрутизацию по ограничениям (US 7444269, 7647211, 7668700); по возрасту, вероятно, истекли, но перед реализацией нужна проверка юристом |
