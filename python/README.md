# bendcore — этап 1: ядро геометрии пути гнутой трубы

Эталонная реализация на Python (без внешних зависимостей, кроме numpy).

Состав:
- `tubegeom.py` — модель пути (прямой участок S, гиб R/B/A, спираль R/p/n), длина по оси,
  касательная T = R·tan(B/2), спираль, нормализация поворота A, проверки, таблица S–A–B → путь,
  центральная линия (ломаная).
- `test_tubegeom.py` — тесты (запуск: `python3 -c "import test_tubegeom as t; ..."` или pytest).

Не входит в этап 1: компенсация пружинения K и B_ст (формула уточняется), развёртка и припуски (этап 2).

Соглашение об A: поворот вокруг текущей касательной перед гибом, относительно плоскости предыдущего гиба.
Спецификацию по этому соглашению надо подтвердить.

## Этап 2 (часть 1): припуски и заготовка — blank.py
- Авто: Δ = max(Δ_мин, N − (S + E)); без подрезки Δ = 0 и S + E ≥ N — жёсткий лимит.
- Длина заготовки = ΣS + ΣR·B + ΣL_спир + E_А + E_Б + Δ_нач + Δ_кон.
- Проверка минимума прямого между гибами (Lmin профиля).
- Тесты: `test_blank.py`. Всего 17 тестов, все проходят.

Не сделано: компенсация пружинения (B_ст, S_ст, n_ст = n/K). Формулы в спецификации (3.6) нужно уточнить.

## Этап 2 (часть 2): компенсация пружинения — compensation.py
- B_ст: теоретический угол, если задан; иначе B·K (предварительно, уточнить в 3.6).
- n_ст = n / K для спирали.
- Длина заготовки с компенсацией: ΣS_ст + ΣR·B_ст + ΣL_спир.ст + E + Δ.
- S_ст пока равен S: формула в спецификации не найдена, открыто.
- При K = 1 и пустом B_ст совпадает с blank_length.
- Тесты: `test_compensation.py`. Всего 21 тест, все проходят.

## Этап 3: данные и библиотеки — library.py
- Слои: системный (только чтение) < предприятия < пользовательский. Побеждает самый приоритетный слой с ключом.
- Импорт CSV: проверки типов, диапазонов, обязательных полей, дубликатов ключа; ссылки между библиотеками.
- Режимы: добавить / обновить / заменить слой. Предпросмотр: добавлено, изменено, пропущено, ошибки.
- Одна транзакция с откатом; «только корректные строки» или «ничего».
- Данные: `data/tubebender_copper.csv` (10 диаметров, медь). Пометки «сверить» сохранены в колонке flag.
- Тесты: `test_library.py`. Всего 28 тестов, все проходят.

Не сделано: импорт XLSX напрямую (сейчас CSV), библиотека трубогибов (K, B_ст, Lmin профиля) как отдельная схема, пользовательский интерфейс.

## Этап 4 (часть 1): 3D-ядро — body3d.py
- sweep_tube: тело трубы по центральной линии, рамка с минимальным вращением (double reflection).
- SpatialIndex: сетка по AABB; 1000 запросов по 5000 объектам — около 0,04 с.
- Document: транзакции (Undo/Redo, откат) и пересчёт зависимостей с обнаружением цикла (список участников).
- Тесты: `test_body3d.py`. Всего 33 теста, все проходят.

Не сделано: порты, ограничения эскиза, спираль в 3D, деформация по сетке, визуализация.

## Этап 4 (часть 2): порты — ports.py (спецификация 5.3)
- Порт: позиция, направление наружу, требуемый ∅, допуск положения и направления (по умолчанию 3 мм и 1°), минимальный вылет, тип соединения, ссылка, занятость.
- Проверки присоединения: занят другой трубой (ошибка), ∅ не совпадает (предупреждение), вылет короче минимума (технологическая ошибка), положение или направление вне допуска (предупреждение), ссылка потеряна (ошибка).
- Трассировка «отсюда»: позиция и направление порта. Кандидаты: свободные порты нужного ∅.
- Тесты: `test_ports.py`. Всего 40 тестов, все проходят.

Не сделано: автопорты при импорте (9.3), фитинги и глубина раструба (9.11), визуализация.

## Этап 4 (часть 3): ограничения эскиза и привязки — sketch.py (1.3, 5.5, 5.6)
- Ограничения: фиксация, расстояние, совпадение с точкой признака, расстояние до плоскости, ∥ и ⊥ оси, равенство длин.
- Решатель: Левенберг–Марквардт (scipy) от текущего состояния; при недоопределённости — метод trf.
- Диагностика: степени свободы по рангу якобиана; конфликт — список ограничений с ненулевой невязкой.
- Привязки: порт > признак > свободно; ортогональный режим (одна ось за шаг); угол по допустимым значениям профиля.
- Тесты: `test_sketch.py`.

Не сделано: приоритет при перетаскивании (размеры > ограничения > авто > форма), ограничения между сегментами и кривыми, пересчёт при смещении компонента окружения.

## Этап 4 (часть 4): обновление и адаптивность — refs.py (5.7)
- Состояния ссылок: валидна / устарела / не загружена / потеряна.
- Обновление компонента: все в норме; вершины сдвинулись (пересчёт решателем, ссылки ставятся на новые признаки); потеряны ссылки (список для диалога).
- Режим трубы: адаптивна или заморожена (заморожена не реагирует на окружение).
- Тесты: `test_refs.py`.

## Этап 4 (часть 5): спираль в 3D — spiral.py (1.2.1)
- Винтовая линия радиуса R (из профиля), шаг p, число витков n (дробное), направление (знак шага).
- Ось навивки задаётся так, что входящая прямая касается спирали: h·a = sinα, tanα = q/(2πR).
  По умолчанию ось лежит в плоскости «направление + верх трубы»; явная ось, не дающая касания, отвергается.
- Начальный угол не вводится: положение входа на витке задаётся точкой входа.
- Длина по оси: n·√((2πR)²+p²). tubegeom.trace разворачивает спираль, касательные стыки проверены тестами.
- Открыто: как пользователь задаёт ось (вспомогательная ось или две точки) — при явной оси
  прямая должна касаться спирали, иначе ошибка.

## Этап 5 (часть 1): модель интерфейса — ui_model.py (6.2, 6.3)
